> These frameworks all build agents, and many have tracing, replay, guardrails and human approval. So the useful question isn't who has checks. It's what a check can honestly say.

This page describes design emphasis. It doesn't claim exclusive features or better answers, because we haven't measured that against any of them. We read each project's docs on November 5, 2026 and didn't run them. These projects move fast, so follow the links before you decide. "Not found" below means we didn't find it in the pages we read, not that it doesn't exist.

## Four questions to ask of any framework

They work on any framework, this one included.

| Ask | agentfootprint |
|---|---|
| Who judged this answer, code or another model? | Code, comparing the answer with the record. No model sets the standing, unless you put one inside your own check. |
| When a check passes, does it call the answer verified? | No. The line reads "This is not a verification." Only a check you wrote can reach known, and the library can't see how it decided. |
| When a search finds nothing, does the answer say what was not searched? | It does when the tool declares it. `absent()` states what was checked and what was not, and the answer reads not sure. |
| Can the person reading see who vouches for each line? | Yes. Explain this answer names the person, library, tool, model or app behind each line, written from the record by fixed templates and never by a model. |

## Where this differs, and what it costs

- **Code does the comparing.** The same record gives the same verdict, and no model is involved. The cost is that it catches contradictions, not meaning. A false sentence built from real values can pass, and a model-graded scorer may catch what this misses.
- **The result is a word with a reason.** The answer's standing is one of five words, not a percentage, and it can reach the person reading. The cost is that "known" rests on a check you wrote, and the library can't see how it decided.
- **The check sits inside the run**, so it can stop an answer before delivery. The cost is that most checks are off until you turn them on, a tool that marks nothing is compared with nothing, and some checks only file what they found without moving the standing yet.

**It holds claims to the record, not to the world.** [How it stands](https://agentfootprint.dev/how-it-stands/) shows each step and its limits.

## How to choose

Choose agentfootprint when a central requirement is to connect an answer to what the agent actually read, the limits of that evidence, and the checks applied before delivery, and you work in TypeScript. You build the agent in agentfootprint, so it replaces your agent loop. It isn't an add-on for another framework.

Look elsewhere when you need:

- **Python.** LangGraph, CrewAI, Pydantic AI and DSPy all work there.
- **A hosted platform with dashboards.** LangSmith, Mastra's platform, CrewAI's platform and Logfire all offer one. agentfootprint is a library, so you host it.
- **Model-graded judgment of meaning on live answers.** Scorers like Mastra's judge what code can't compare.
- **Automatic prompt optimization.** That's DSPy's focus.
- **Images or video in messages.** `LLMMessage.content` is a string today.
- **Prompt injection detection out of the box.** It isn't in core. See [Security](https://agentfootprint.dev/security/) for what is, and what to add.
- **No change.** If your team is shipping and happy with what it has, don't switch on hype.

## Migration

- **From LangChain.** Agent code maps to `Agent.create({ provider, model }).tool(...).build()`. Tools are `defineTool({ name, description, inputSchema, execute })`. Memory becomes `defineMemory({ type, strategy, store })`. Middleware that adds context becomes an Injection, such as `defineSteering` or `defineInstruction`.
- **From LangGraph.** Nodes become `Sequence` steps, and conditional edges become `Conditional`. Retry policies map to `.reliability({...})` rules at the agent level, and interrupts map to `pauseHere()` and `resume()`.
- **From CrewAI or AutoGen.** A crew of agents with tasks becomes a `Sequence` of agents. Roles and goals become system prompts or Steering injections. Tools work the same way.
- **From DSPy.** A compiled prompt becomes a Steering injection (`always` trigger, `system` slot). DSPy still does the optimizing offline, and agentfootprint does the runtime composition.
- **Alongside Inngest.** Keep it for queues and cron, and call agentfootprint inside a step.
