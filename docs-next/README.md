# agentfootprint docs

A Next.js 16 + [Fumadocs](https://fumadocs.dev) (React-native, AI-native) documentation
site for **agentfootprint** — the published docs at
https://agentfootprint.dev/. (Migrated from a former Astro/Starlight
site, now removed.)

## Why Fumadocs (vs the Starlight site)

- **React-native** — the interactive "Run → runtime flowchart next to the code" feature
  (porting `explainable-ui` + the `footprint-playground` runner) is first-class here,
  not an island bolted onto a non-React framework.
- **AI-native** — `llms.txt` / `llms-full.txt`, per-page raw Markdown, and MCP are
  native rather than plugin-bolted (on-brand: our whole thesis is machine-legible systems).
- **Anti-drift preserved** — examples-as-tests + build-time code-from-source + Twoslash
  (compile-checked code blocks) carry over from the Starlight discipline; Twoslash also
  closes the gap where hand-written inline snippets could rot.

## Develop

```bash
(cd .. && npm ci && npm run build)
npm ci           # also runs `fumadocs-mdx` (codegen → .source/)
npm run dev      # http://localhost:3000 → /docs
npm run build    # static/server build
```

The site builds against the AgentFootprint source beside it. The docs build,
Try-it and type checks verify that source and its locked dependencies.
The separate `docs-demo` app builds its viewer examples from published packages.
The docs use npm's `install-links` setting to pack the built `file:..` dependency into
the docs install, where the site and AgentFootprint share one FootPrint and
Foottrace package. Run `npm ci` again in the docs after rebuilding the root source.

The browser demos share AgentFootprint's installed FootPrint engine and Foottrace record
implementation. `next.config.mjs` derives exact aliases from both packages' public
exports so code in the site's browser examples and the AgentFootprint runtime
resolve the same physical copies. Webpack applies these aliases only to the client,
leaving its server resolution unchanged. Turbopack's existing global alias policy
also covers Foottrace, using relative paths to the same files. `check:browser-demos`
checks every public door and Webpack's unchanged server resolution. With
`DOCS_WEBPACK_STATS=1`, the build also writes module statistics for inspecting
bundle contents.

## Visual context walkthrough

`/context-engineering/` teaches context preparation and conflict handling through
two illustrated, ordered stories. The answer story includes selected context
values from a recorded synthetic run and links each step to the native Lens
inspector in the versioned demo. The conflict story shows its authored JSON as
illustrative data. Both stories are readable without scripting.

Run `npm run gen:context-walkthrough` from `docs-demo` to update the selected
values from the pinned mock run. The site's current-library Try-it check runs
the same fixture and verifies its tool result and answer check. The demo checks
verify the native milestone selector and return links. `EXPORT=true npm run
build`, `npm run check:links`, and `npm run check:site-budget` include the
page in the normal static-site checks.

## Layout

| Path | What |
|---|---|
| `content/docs/**.mdx` | the documentation content |
| `source.config.ts` | Fumadocs content config (frontmatter schema, dir) |
| `lib/source.ts` | the content-source loader (`/docs` base) |
| `app/docs/[[...slug]]/page.tsx` | the docs route |
| `app/static.json/route.ts` | static Orama search index |
| `lib/search-index-order.mjs` | canonical URL/ID order before indexing |
| `.source/` | generated by `fumadocs-mdx` — **not committed** |
| `assets/originals/` | Image originals retained for editing; optimized versions in `public/` serve the site. |

Static export also runs `scripts/prune-export.mjs`: it removes duplicate full RSC
payloads and the internal `_not-found` route when both public 404 pages are
identical, the internal file set is recognized, and no HTML links there. Public
404 pages, their JavaScript, and every documentation route remain. Export-shape
changes retain the internal route for review; `check:export-prune` tests these
refusals before each build. Site budgets remain unchanged.

Search indexing must not depend on asynchronous file discovery. The pure
`orderSearchIndexes` helper sorts complete page records by URL, then ID, using
codepoint order. It preserves every record and field; equal-score search ties
now follow a reproducible order. `check:search-index` verifies nonmutation and
byte-identical real Orama exports across input permutations before each build.

## Auto-generated API reference (anti-stale infra)

The full API reference under `content/docs/api/**` is **generated from TypeScript
source** by [`../scripts/gen-fumadocs-api.mjs`](../scripts/gen-fumadocs-api.mjs)
(TypeDoc + `typedoc-plugin-markdown`, config in
[`../typedoc.docs-next.json`](../typedoc.docs-next.json)). The script:

1. **cleans** `content/docs/api/` then regenerates — a removed/renamed export leaves
   **no stale page** behind;
2. post-processes each page to be Fumadocs-ready (adds `title` frontmatter, rewrites
   internal links, writes sidebar `meta.json`).

It runs as **`predev` / `prebuild`**, so dev and production builds always reflect the
current source. The generated `.md` files **are committed** (reviewable diffs + the
site builds without re-running TypeDoc).

```bash
npm run gen:api      # regenerate the API reference now
npm run check:api    # CI guard: regenerate + `git diff --exit-code` (fails if stale)
```

Wire `npm run check:api` into CI so a PR that changes the public API but forgets to
regenerate docs fails the build — the no-stale-docs guarantee.

### Skill graph figures

The two skill graph guides show the declared maps recorded from mock runs in the
[separately locked demo](../docs-demo/README.md). Run `npm run gen:skill-graphs`
in `docs-demo` to refresh the checked-in figures. This site renders the Quickstart
example's Mermaid source with the current library and verifies both graphs with
`npm run check:tryit`. The static export also includes the demo's fallback sections.
