**A cancelled or timed-out MCP gateway call is no longer sent when its credential arrives late.** `gatewayTransport` vends a credential inside every request, and that wait ignored the request's abort signal. A stalled `CredentialProvider` kept a cancelled call pending, and a credential that arrived after the call was cancelled, or after the retry deadline passed, still sent the request, so the server could run a call nobody was waiting for. The vending fetch resolves the request's signal as fetch does (`init.signal`, or a `Request` input's own) and now asks no provider for a request already aborted. It hands the provider that signal as the new optional `CredentialRequest.signal`, ends the wait at the abort with the abort, and checks the signal again once the credential arrives, before the request is handed on. A provider that honours the signal stops. One that ignores it may still finish its own work, but it can no longer hold the call open or have the request sent late: the gateway drops its credential unused. `withCredentialRetry` passes the signal through, ends its backoff wait on it, and checks it immediately before every attempt, the first included, so a request whose signal has fired never asks the provider again, even after a zero-length wait or an `onRetry` that cancelled it. The agent's own credential resolution and `mcpServe` do not pass a signal yet. With no abort, every request is vended and sent exactly as before. `CredentialRequest.signal` is an optional field, so existing providers and callers compile unchanged.
