**A cancelled or timed-out MCP gateway call is no longer sent when its credential arrives late.** `gatewayTransport` vends a credential inside every request, and that wait ignored the request's abort signal. A stalled `CredentialProvider` kept a cancelled call pending, and a credential that arrived after the call was cancelled, or after the retry deadline passed, still sent the request, so the server could run a call nobody was waiting for. The vending fetch now asks no provider for a request already aborted. It hands the provider the request's signal as the new optional `CredentialRequest.signal`, ends the wait at the abort with the abort, and checks the signal again once the credential arrives, before the request is handed on. A provider that honours the signal stops. One that ignores it can no longer hold the call open or send it late: its credential is dropped unused. `withCredentialRetry` passes the signal through, ends its backoff wait on it, and never retries a request whose signal has fired. With no abort, every request is vended and sent exactly as before. `CredentialRequest.signal` is an optional field, so existing providers and callers compile unchanged.
