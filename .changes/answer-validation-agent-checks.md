**Let the agent's own answer checks withhold an answer instead of only flagging it: `.answerValidation({ agentChecks })`.** On their own, `.claims()` records a typed answer field that contradicts the fact a tool settled, and `.namesAndNumbersFromEvidence()` (default `'assist'`) records a value no tool result carried — and either way the answer is handed back. List them, `agentChecks: ['claims', 'names-and-numbers']`, and each finding becomes a failed row of the same report your own checks fill: an enforcing validation withholds the answer (`AnswerValidationError`, with no draft token streamed), and `mode: 'observe'` records the rows and delivers. Under `posture: 'guard'` the gate's one repair turn runs first, with the tools still on the wire, and only what survives it is withheld. A claim that states a value for a fact no tool result settled is `unreachable`, so it is withheld too. The gate's clean pass is filed `not-applicable`: finding a value clears an answer but never verifies it, so the gate alone never makes a report pass. Rows carry counts and the field names you declared — never the answer's or a tool's values, nor the entity a contract names. Each listed check needs its builder call, or `build()` refuses, and check ids starting `agent:` are reserved while the option is set. Without `agentChecks`, nothing changes.
