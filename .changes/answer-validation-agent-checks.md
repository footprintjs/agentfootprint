**Let the agent's own answer checks withhold an answer instead of only flagging it: `.answerValidation({ agentChecks })`.** On their own, `.claims()` records a typed answer field that contradicts the fact a tool settled, and `.namesAndNumbersFromEvidence()` (default `'assist'`) records a value no tool result carried — and either way the answer is handed back. List them, `agentChecks: ['claims', 'names-and-numbers']`, and each finding becomes a failed row of the same report your own checks fill — every row judged on the exact JSON the validation delivers, after any output transform, never on the model's draft: an enforcing validation withholds the answer (`AnswerValidationError`, with no draft token streamed), and `mode: 'observe'` records the rows and delivers. Under `posture: 'guard'` the gate's one repair turn runs first, with the tools still on the wire, and only what survives it is withheld. These rows withhold and never verify: no agent row is ever `checked-pass`, so `validate` stays required and only your own checks can make a report pass. A claim that agrees with the fact is `not-applicable`, because a `.claims()` contract is unscoped — it reads the latest value any tool result settled for that entity and field, with no scope or age check — so agreement may be with another customer's record or a stale read; a contradiction still withholds the answer. A claim that states a value for a fact no tool result settled, for one this run's tool results settled two different ways, or against a tool's bare `null` or `'unknown'`, is `unreachable`, so it is withheld too — and so is agreement on doubt (the tool settled only `null` or `'unknown'` and the answer gives no value): it verifies nothing, so enforce withholds it and observe delivers it with the standing "not sure", never "known". The gate's clean pass is filed `not-applicable`: finding a value clears an answer but never verifies it. Rows carry counts and the field names you declared — never the answer's or a tool's values, nor the entity a contract names. Each listed check needs its builder call, or `build()` refuses, and check ids starting `agent:` are reserved while the option is set. Without `agentChecks`, nothing changes.
