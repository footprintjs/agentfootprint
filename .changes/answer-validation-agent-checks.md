**Let the agent's own answer checks withhold an answer instead of only flagging it: `.answerValidation({ agentChecks })`.** On their own, `.claims()` records a typed answer field that contradicts the fact a tool settled, and `.namesAndNumbersFromEvidence()` (default `'assist'`) records a value no tool result carried — and either way the answer is handed back. List them, `agentChecks: ['claims', 'names-and-numbers']`, and each finding becomes a failed row of the same report your own checks fill — every row judged on the exact JSON the validation delivers, after any output transform, never on the model's draft: an enforcing validation withholds the answer (`AnswerValidationError`, with no draft token streamed), and `mode: 'observe'` records the rows and delivers. Under `posture: 'guard'` the gate's one repair turn runs first, with the tools still on the wire, and only what survives it is withheld. These rows withhold and never verify: no agent row is ever `checked-pass`, so `validate` stays required and only your own checks can make a report pass. A claim that agrees with the fact is `not-applicable`, because a `.claims()` contract is unscoped — it reads what any tool result settled for that entity and field, with no scope or age check — so agreement may be with another customer's record or a stale read; a contradiction still withholds the answer. The claim row can only withhold: it reads every reading of the fact the run made, never the latest alone, and one more reading never makes it more permissive, so a forged or stale reading can at most withhold an answer. A fact no tool result settled is `not-applicable` — not checked — and your own checks decide. A contradiction found is reported as one: a field that contradicts any value the run read fails its row, whatever else was read — a fact read as 900 and as 1250 fails an answer of 1250. Claims are compared after one declared normalization, so a different spelling is never a contradiction: text is compared in Unicode NFC, trimmed, with its white space collapsed, and case agrees only for a word of letters, more than three of them, with the same letters in another case (`'Settled '` agrees with `'settled'`, `'STRAẞE'` with `'Straße'`) — a rule that cannot know where case carries meaning, so `'Polish'` agrees with `'polish'` and `'AIDS'` with `'aids'` (leave such a field out of `.claims()` and compare it in `validate`); a number and a string written as a plain decimal compare by value both ways (`42.5` agrees with `'42.50'`); and a number with a unit compares only with the same unit, written exactly (`'5 MW'` is not `'5 mW'`). Values that cannot be compared safely are `unreachable`, never a failure: a list against a single value, `'1250 ms'` against `1250`, any other case difference (`'MW'`/`'mW'`, `'Co'`/`'CO'`, a mixed-case word, text with a digit, `ß` against `ss` in any casing such as `'Masse'`/`'maße'` or `'MASSE'`/`'Maße'`, `'ılık'`/`'ilik'`), a list with a hole in it, and a value written with a currency symbol, digit separators, a dot-grouped number (`'1.250'`), a date or a time unless both are written the same. A claim that contradicts none of the values read is `unreachable`, so it is withheld, when the readings differ (`900` and `'900 ms'`, answer 900) or one settled the fact only as unknown, `null` or `'unknown'` (in any case) beside the stated value — and so is agreement on doubt (the tool settled only doubt and the answer gives no value): it verifies nothing, so enforce withholds it and observe delivers it with the standing "not sure", never "known". A value or reading that is not a well-formed `Claim` (a `known(…)` without its `evidence`, an `unknown(…)` carrying a `value`) is never read: `unreachable`. The gate's clean pass is filed `not-applicable`: finding a value clears an answer but never verifies it. The gate reads the first 20,000 words and numbers of an answer; a longer answer makes its row `unreachable`, with the reason naming how many more were never looked up, so an answer is never cleared on the part the gate read. Three limits to know: a fact whose value changes during the run (a status polled from `'queued'` to `'done'`, a balance before and after a write) is withheld, because every reading counts — settle it once (leave it out of the result until final, or poll inside one tool call), model before and after as separate fields, or leave it out of `.claims()` and check it in `validate`; claims are checked against the tool results THIS run read, so a follow-up turn that answers from an earlier turn's read without reading again is not checked (your checks decide); and the gate's `minDigits` floor (default 4) means short numbers are not looked up — lower it, or declare `shapes`, when short numbers are data. Rows carry counts and the field names you declared — never the answer's or a tool's values, nor the entity a contract names. Each listed check needs its builder call, or `build()` refuses, and check ids starting `agent:` are reserved while the option is set. Without `agentChecks`, nothing changes.
