**An abort while a stream is closing now rejects and closes the transport, and a chunk read just before an abort is never handed on.** Two cancellation gaps in every streaming provider adapter. First: when a consumer stopped a stream early (`break`, `return()`) and the transport's close did not finish, an abort that fired during that wait resolved the close as a clean finish and never ran the adapter's own close — the SDK stream (Anthropic's `abort()`, OpenAI's controller) stayed open. It now rejects with the caller's abort reason and closes the transport. Second: a body read that settled a moment before the abort, but whose reader had not yet run, was still handed on — so the raw-`fetch` adapters (browser Anthropic/OpenAI/Azure, Ollama, Foundry Local, the InvokeModel gateway) could yield, and bill, a chunk after the caller had cancelled. The signal is now checked again after every read. Both cases are in the shared adapter cancellation conformance, which now also runs against the built package in ESM and CJS.
