**The evidence gate can now catch an invented figure like "53.2% used, 6.3 TB free" — `namesAndNumbersFromEvidence({ figures: true })`.** A number with a unit of measure stuck to it (`%`, `TB`, `GB`, `IOPS`, `ms`, …) used to be prose to the gate whenever it had fewer than four digits, so an answer whose every figure was made up passed as clean. With `figures: true` such a number is checked like any other value, whatever its length. A number no tool result carried is then checked against a fixed set of calculations over the numbers the results do carry: rounding, a unit conversion (steps of 1000 or 1024), a column sum (over all rows, or over the rows sharing one text value), a like-unit ratio or difference of column sums, or a complement of a percentage. So the honest "1,526.3 TB usable in total" is accepted, and named on `evidence_checked.computed` with the calculation that gives it, instead of being flagged as invented. A number that matches nothing is flagged, and the warning says it matched no value and no calculation. Under `guard`/`rails` the revision request also ends with one request-only line from the library naming the flagged numbers and telling the model to say so plainly when no result shows the figure. `servedAt` rebuilds that line with reason `'evidence-conclusion'`. Off by default; without the option the gate is byte-identical.
