**Prompt caching now hits behind `withRetry`, `withFallback` and your own provider wrappers — the cache strategy is chosen from what the provider declares, never from its name.** The agent used to look its cache strategy up by `provider.name`. Any decorator that renamed the provider — `withRetry` (`anthropic+retry`), `withFallback` (`a|b`), an application's routing wrapper (`my-app/anthropic`) — fell through to the no-op strategy: no cache markers, every call at full input price, nothing in the run to say why. Measured on the inputs bench's recorded cases (`bench/cache/run.mjs`, $0, the real Anthropic adapter): the share of each repeat call a cache can serve went from **0% to 84.5%** behind `withRetry` or an app wrapper.

Each provider adapter now DECLARES how its wire caches — `LLMProvider.promptCaching` (type `PromptCaching`, from `agentfootprint/cache`): `{ mode: 'breakpoints', maxBreakpoints, reportsUsage }` (`anthropic()`, `browserAnthropic()`), `{ mode: 'automatic', reportsUsage }` (`openai()`, Azure OpenAI, Foundry), or nothing (no caching) — and `cacheStrategyFor(provider)` picks `BreakpointCacheStrategy`, `AutomaticCacheStrategy` or `NoOpCacheStrategy` from it. `withRetry`, `withCircuitBreaker` and `withFallback` forward it. A malformed declaration is refused at build, by provider name.

Two more changes to what is marked, never to what the model reads (the same run with `caching: 'off'` sends the same bodies once the markers are stripped): the conversation's last message now carries a **moving breakpoint**, so each call reads back everything the previous call sent (a bare `anthropic()` agent's repeat calls: 75.4% → 84.5% served) — but only when every system piece and tool before it is cacheable: `defineInstruction` defaults to `cache: 'never'`, so an agent with one default instruction places no conversation breakpoint and gains nothing from it (66.7%, as before); give the instruction a `cache` policy to change that; and under `.findings()` no marker is placed at all — the findings offer rewrites every tool schema per call, so the markers were paying the cache-write premium on 97% of the request bytes while the repeat calls read back 5% of theirs. Receipts record the strategy by the capability it serves (`cache.strategy`: `'breakpoints'`, `'automatic'`, `'none'`; it was the registry key, `'anthropic'`, `'openai'`, `'*'`), and `agentfootprint/cache` no longer registers anything at import (it left the package's `sideEffects` list).

**The thinking handler is declared the same way.** It was also matched by `provider.name`, so a renamed provider mounted no thinking stage and Anthropic's signed thinking blocks never reached the assistant turn they must be echoed on. Each adapter now declares `LLMProvider.thinkingHandler` (`anthropic()`, `browserAnthropic()` and — newly, since it parses the same response — `invokeModelGateway()`; `openai()`, `ollama()`, `mock()`), every wrapper forwards it, and `withFallback` tags each response's raw thinking with the side that answered and runs THAT side's handler (sides with different handlers used to lose it, so the next `.thinking()` call with tools was a 400) — and hands each side only the cache markers that side declares, so a side that declares no caching never sees `cache_control`. `thinking_parse_failed.providerName` now names the agent's provider. Azure OpenAI and Foundry agents inherit `openai()`'s handler, so they now mount the NormalizeThinking stage: two more commits per call in their trace (it reads nothing — the OpenAI adapter emits no raw thinking). A redacted thinking block now keeps its encrypted `data` and is echoed as `{ type: 'redacted_thinking', data }`; it was dropped, so the echo was a 400.

Migration: `registerCacheStrategy`, `getDefaultCacheStrategy` and `listRegisteredStrategies` are gone — declare `promptCaching` on your provider instead, or pass `Agent.create({ cacheStrategy })`. `AnthropicCacheStrategy` is `new BreakpointCacheStrategy({ mode: 'breakpoints', maxBreakpoints: 4, reportsUsage: true })`; `OpenAICacheStrategy` is `new AutomaticCacheStrategy({ mode: 'automatic', reportsUsage: false })`; `BedrockCacheStrategy` is `NoOpCacheStrategy`; or call `cacheStrategyFor(provider)`. A custom `CacheStrategy` renames `providerName` to `name` and drops `capabilities` (the `CacheCapabilities` type is removed — the provider's declaration is the one place a capability lives). A provider wrapper you wrote forwards one more field, beside `carriesInMessages`: `...(inner.promptCaching !== undefined && { promptCaching: inner.promptCaching })` — without it the wrapper runs uncached, and its receipts say `'none'`. The same for thinking: `findThinkingHandler` and `ThinkingHandler.providerNames` are gone — declare `thinkingHandler` on your provider (or pass `.thinkingHandler(h)`), forward `thinkingHandler` in a wrapper, and drop `providerNames` from a custom handler; `thinkingHandlerFor(provider)` reads a declaration.
