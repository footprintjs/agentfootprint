**A client per conversation for an MCP server: `mcpClientPool()`.** A `'reuse'` session (AgentCore Runtime, or any stateful MCP server) saves the cold start only when every conversation has a client of its own. The pool keeps one client per authenticated conversation, keyed by the identity the caller named in `run({ identity })` (never a derived one), opens each one once under its own deadline, and hands an agent that conversation's tools through `pool.toolProvider()`. Three budgets — open clients (`maxClients`, `maxClientsPerPrincipal`), endings (`maxEnding`) and operations outstanding on any client (`maxOperations`) — are each charged until the work under them has settled, not merely until a caller gave up; a full budget is `PoolFullError` at once, never a queue. Tool lists are per client by default and shared only under names you declare (`definitions.share`) and a matching configuration; every bound tool re-checks its binding after each wait and at every boundary its request crosses, so a tool revoked by `permissionsChanged()`, `toolsChanged()` or the server's own notice is refused before it is sent. `pool.terminate()` ends a conversation's remote session and reports what the server answered (`McpTerminateOutcome`), `acquire()` holds a client across a turn, and `stats()` counts what is charged, unsettled and unresolved. Every use is recorded as `agentfootprint.tools.mcp_client` — ids and outcomes, never an identity, a session id or a result.

**`McpClient.terminate()`.** `close()` does not end the remote session; `terminate()` does, and says whether it did — `remote` (`'terminated'`, `'already-gone'`, `'no-session'`, `'not-offered'`, `'failed'`, `'timed-out'`, `'handle-lost'`, `'unavailable'`) and `resolved`. Optional on `McpClient` (ask `canTerminate(client)`); `mcpClient()` and `mockMcpClient()` provide it. Under AgentCore Runtime's `session: 'reuse'` it is `StopRuntimeSession` for that client's runtime session (pass `StopRuntimeSessionCommand` in `sdk` beside the other two commands when you supply the module). A server's 404 for its own session is `SessionExpiredError` (the existing class, `evidence: 'server-404'`); a handle this process lost is the new `LocalSessionHandleLostError`. `ToolDispatchContext.callerIdentity` carries the identity the caller named, absent when the run's identity was derived.

Changed, for direct `mcpClient` users of an AgentCore Runtime transport with `session: 'reuse'`: a request carrying a handle the transport does not hold (one it never issued, or one its 256-entry memory forgot) now fails with `LocalSessionHandleLostError`, unsent, instead of a 404 the transport made up — nothing was sent and no server ended anything. A client's `DELETE` now stops its runtime session instead of only forgetting the handle. Every transport the library builds now carries a pass-through `fetch` that reads a `DELETE`'s status; it changes no request.
