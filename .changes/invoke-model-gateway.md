**`invokeModelGateway()` — Anthropic models behind your gateway's InvokeModel wire.** Many organisations reach Claude through their own gateway: plain HTTPS, an API-key header, and the Bedrock InvokeModel operation (`POST {baseUrl}/model/{id}/invoke` and `…/invoke-with-response-stream`). `bedrock()` signs with AWS credentials against Converse and `providerFromEnv()` has no base URL for this wire, so an app had to write its own adapter. Now it is one call from `agentfootprint/providers` (or `createProvider({ kind: 'invoke-model-gateway' })`): `complete()` and `stream()` (the SSE the gateway already decoded — text deltas, tool arguments reassembled from `input_json_delta`, the terminal chunk carries the response), `system` on the top-level field, `tool_use` blocks both ways, forced tool choice, and a key chosen per model id (`apiKey` as a string, a map, or a function re-read before every request). Every failure is an `InvokeModelGatewayError` naming the model — a 403 says the key is scoped away from that model — with `status` set for HTTP refusals, so `withRetry(invokeModelGateway({...}))` retries 429 and 5xx and nothing else; the adapter has no retry loop of its own. The Anthropic Messages body `browserAnthropic()` sends now has one shared owner (`anthropicMessagesWire.ts`); `browserAnthropic()`'s requests, responses and streamed chunks are pinned byte-identical.
