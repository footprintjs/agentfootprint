**`invokeModelGateway()` — Anthropic models behind your gateway's InvokeModel wire.** Many organisations reach Claude through their own gateway: plain HTTPS, an API-key header, and the Bedrock InvokeModel operation (`POST {baseUrl}/model/{id}/invoke` and `…/invoke-with-response-stream`). `bedrock()` signs with AWS credentials against Converse and `providerFromEnv()` has no base URL for this wire, so an app had to write its own adapter. Now it is one call from `agentfootprint/providers` (or `createProvider({ kind: 'invoke-model-gateway' })`): `complete()` and `stream()` (the SSE the gateway already decoded — text deltas, tool arguments reassembled from `input_json_delta`, the terminal chunk carries the response), `system` on the top-level field, `tool_use` blocks both ways, forced tool choice, and a key chosen per model id (`apiKey` as a string, a map, or a function re-read before every request). Every failure is an `InvokeModelGatewayError` naming the model — a 403 says the key is scoped away from that model — with `retryable` set (`true` for a 429, a 5xx and a network failure, `false` for everything else), so `withRetry(invokeModelGateway({...}))` retries exactly those three: a missing key or model is refused once with no backoff wait, and a 2xx it could not read is never re-sent to a model that may already have run. The adapter has no retry loop of its own. `withRetry`'s default predicate (shared with `withCredentialRetry`) now skips any error that declares `retryable: false`; an error without the field is judged exactly as before. The Anthropic Messages body `browserAnthropic()` sends now has one shared owner (`anthropicMessagesWire.ts`); `browserAnthropic()`'s requests, responses and streamed chunks are pinned byte-identical.
