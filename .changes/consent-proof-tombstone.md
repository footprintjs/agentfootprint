**"Did not run" is proven by a tombstone in the ledger the request was minted under, and every callback before a call runs sees one frozen copy of it.** A review round on the two follow-ups above.

**The proof.** A hosted door (`standingAgent`, `streamHandler`) that closes a pause no answer can reach now records its calls as not run only when the ledger the request was MINTED under spends the request itself: `true` means no decision had reached it and, in the same atomic step, that none ever can — a resume that arrives later, on any replica, is refused as `'already-answered'`. Before, the door read `isSpent` and then wrote the close, so a resume on another replica could run the refund in between, and a ledger that expires keys could read a spent request as unspent. Rules:

- Only the minting ledger proves. A consent pause now records the identity of the ledger its request was minted under (an optional `ledger` field on the paused state's request record; a pause stored before it reads as unproven). A redeploy that switched from the default ledger to a shared one asked a ledger that never saw the spend and wrote "did not run" — the original bug; it now records the call as possibly run.
- A ledger proves only with a stable identity. **Added:** the optional `DecisionLedger.id` — the same in every process that shares the ledger. A ledger without one (an app's own `inMemoryDecisionLedger()` included) never proves. For a ledger that is to prove, `spend` must be atomic and its result permanent: no expiry.
- This process's default ledger has a per-process identity: a restart can never prove a pause an earlier process stored, and it proves only when the pause is kept in this process's memory (`memorySessions()`). With a store other processes reach, another replica on its own default ledger may have spent the request and run the call. Several processes need one shared `decisionLedger`; switching ledgers leaves every pause minted under the old one unprovable.

**What the model is told.** A call that may have run reads "This call may have run; no result was kept. Do not run it again. Tell the person it may already have happened and ask them to check." — the same for the paused call and a sibling that never needed approval. The notice for a call a failed resume left open ends with the same last sentence. Every host notice is now marked as the library's (`toolResultOrigin`), whether or not the run served findings; the marker never reaches a provider. The refusals that describe a closed pause now say "recorded as not run only when proven, otherwise as not known".

**Arguments before a call runs.** `tool_start` carried the live arguments: a listener that set `amount = 9000` refunded 9000. It now carries a frozen copy. One frozen copy per call is shared by `tool_start`, the permission checker, a capability check, the `checkIn` predicate and — on a pause — the request shown and its evidence assembler (it is frozen, so sharing is safe; a large argument is copied once instead of once per callback). The history handed to those callbacks carries the batch's assistant turn as a frozen copy too, so a callback that casts away `readonly` cannot reach a call's arguments through it; earlier turns are handed as they are (their calls already ran, and copying the whole conversation per call would cost O(conversation)). In dev mode, the first write into a frozen copy by each kind of callback prints one warning naming it — a permission checker that normalised its `context` in place denied every call in silence.
