**The evidence gate reads a typed answer value by value, so compact JSON no longer turns correct numbers into invented ones.** A typed answer written the way `JSON.stringify` writes it was tokenised as text. `{"total":1200}` kept the key's colon on the value, and `:1200` was looked up as an identifier no tool result carried. `[5,100]` read as the thousands-separated `5100`, and `[0.45,0.12]` as one identifier. Correct answers were flagged: `'guard'` spent its one revision on them and `'rails'` refused them. `[1200,9750]` read as no value at all, so an invented number in an array was never looked up.

An answer that is one JSON object or array — what `.outputSchema()` accepts — is now read value by value: every string decoded, every number the literal the answer **wrote**, read left to right in one pass after `JSON.parse` has checked the grammar. Under `.outputSchema()` the object keys are the schema's field names and are not judged, so a digit-bearing name such as `p95LatencyMs`, `sha256` or `q3Revenue` is never taken for an invented identifier; an answer keyed by data (an id as a key) is therefore not checked on its keys, so keep such ids in values. Without a schema, a JSON-shaped answer's keys are read too. A number is never read through the double it parses to, so `9007199254740993` is not taken for `9007199254740992`, a 20-digit serial is not rounded, and under `decimalRounding` a written `5.20` keeps the precision the rounding rule judges.

In text, the shared spelling rule now reads a JSON key's colon — the one right after a key's closing quote — as a separator, on both the answer's side and the results' side, so `export ok: {"total":1200}` carries `1200`. Every other colon is part of the value it sits in: an IPv6 address (`::1234`, `fe80::1`, `2001:db8::1234`, `::ffff:192.0.2.1`) is never matched by the number after its colons, at the gate or by the inputs layer's `sameArgumentValue`, and a quoted `":8080"` keeps its colon. One consequence is worth knowing: a three-digit number in compact JSON is no longer a candidate. Before, it was flagged only by the `:123` accident, so this is now the same `minDigits` rule prose gets.
