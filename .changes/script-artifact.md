**Show the script an answer was computed with — attached from the run record, and matched byte for byte when the model shows it.** A tool now declares that it runs a program (`script: { argument, language? }` on `defineTool`; `codeRunnerTool` declares it), and each call of it files the program it was handed and what its runner reported. `.scriptTravelsWithTheAnswer({ which, maxBytes })` attaches that recorded program under the answer — text after the `---` separator on a prose answer, data on `turn_end.scripts` always — so "always show the script" holds without the model retyping anything. `.namesAndNumbersFromEvidence({ code: 'match' })` reads a fenced block the model wrote as script content only when it equals, byte for byte after removing the Markdown wrapper, a program this turn's call submitted: no value candidates, labelled with that call's outcome; anything else stays prose, checked as before, and labelled `unmatched` (`evidence_checked.scripts`, each flagged value's `region`). Code is never evidence for a value. Labels say only what the record proves: `completed, exit 0` needs an explicit exit code; a bare runner verdict is "runner reported success/failure; no exit code"; a timeout, a cancellation or a service error with no exit code is "outcome unknown"; a tool that returned with no runner facts is "tool call returned; execution not confirmed". Under the answer layer an unmatched block reads "not sure" (`script-unmatched`), and the answer account says which script was shown or attached and what its call reported. Bounded in UTF-8 bytes: 32,768 per program, 16 calls a turn, 32 blocks an answer, 4,000 attached by default; a program's text is kept for its own turn only. The match reads a block where a CommonMark renderer shows one: a block closes at a fence indented by up to three spaces, a lone CR ends a line, and reading stops at the first line where a renderer could pair fences another way. That is a fence indented inside a list, an HTML block, a `$$` math line, a closing fence with a trailing tab, or a block holding a fence run as long as its own fence. Everything after that point is prose. So a program cannot be shown in a way that carries a sentence past the block's close, unchecked. The audit chain's bounded mode replaces each attached program on `turn_end.scripts` with `'[N chars]'` and keeps its labels and counts. The `tools.code_run` event now also fires for a call that runs on the far side of a check-in, consent or ask pause. `code: 'check'` (the default) and an agent without either option are byte-identical.
