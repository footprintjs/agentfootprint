**Where each argument value came from — the model says so, the library checks it: `.findings({ argumentSources: true })` (the inputs layer's declared sources).** On an agent whose inputs layer is armed (a tool that declares `askOrAssume`, or `.inputsLayer()`), the model can say, per argument of a ruled call, where the value came from — in the reserved `_findings` argument it already writes: `from: [{ argument: 'window', source: 'user', quote: 'over the last week' }]`. The sources are `user` (the person's words, copied as a `quote`), `result` (a tool_result `id`), `turn` (the person's earlier answer to the library's ask), `app` (the app's own text) and `assumed`. Before anything in the batch runs, the library CHECKS each claim against the one place that source lives, by whole-token membership (the evidence gate's own normaliser): the quote must be in the person's own messages — never a library frame, never another runner's output — and the value in the quote, or a phrase the author vouches for on that value's choice (`choices: [{ value: '7d', said: ['last week'] }]`); the value must be in the named result's own bytes (read the way the evidence index reads a result, so a number or a boolean in compact JSON is found, and the library's own note on a result never counts); an earlier answer matches the same argument, or a period across spellings (`24h` ↔ `-24h`, `matched: 'spelling'`); `app` looks in the system messages, the composed system prompt (the library's own instructions left out) and `AgentOptions.externalGrounds` (its label rides `appSource`).

The verdict is filed on the call's `argument` row: `source` `said` (`matched: 'quote' | 'phrase'`, or `reading` when the words are the person's and the value is not in them), `answered`, `result` (`setAside` when the model had declared that result open, noise or ruled out), `app`, `default` or `model`; the claim as written (`claimed`, `quote` — `'REDACTED'` whenever the tool's own argument view hid any argument of the call, since a quote is free text that may hold another argument's value); a failed check (`failed`: `quote-not-found`, `composed-message`, `unknown-result`, `placed-result`, `not-in-result`, `no-earlier-turn`, `not-in-earlier-turns`, `only-in-model-answer`, `not-in-app-text`, `uncheckable`) is never repaired; a library lookup of the value is only a hint (`coincides`), never a source. A value equal to the argument's declared default that is not the person's stays `default`, whatever the claim. A free argument a `from` entry names is checked and filed with no rule; dropped `from` entries are counted on the basis row, or on the call's first argument row. The event `agentfootprint.findings.argument` carries the new enums, never a value or a quote.

What changes: under an `ask` rule, a PRESENT value the checks do not trace to a source — nothing declared, `assumed`, a failed claim, a reading — is now asked of the person in the batch's one ask (`asked: 'unverified'`; the model's value rides the row as `proposed`, never the ask); a reading's field shows the person their own words (`context.agentfootprint.fields[].quoted`); the answer replaces the value and the result's note says what the call had carried. The answer's standing gains two reasons — `argument-read` and `value-contingent` (now also read from the ledger's contingent rows of the turn) — and a failed claim on any argument reads `argument-unverified`; a traced value fires nothing, so checked values read "consistent with the record", never "known" (a membership pass supports nothing). `checked` gains `argument-sources`. The answer account's template set moves to 5 (`howSure.reason.argumentRead`, `howSure.reason.valueContingent`, `howSure.check.argumentSources`; `howSure.reason.argumentUnverified` no longer says "ruled").

Compositions mark another runner's output: `Sequence` (every step after the first) and `Loop` (every iteration after the first) hand a runner that reads the mark `messageFrom: 'composed'`, and `Parallel`, `Conditional` and a nested composition pass a composed message on — so another model's words never count as the person's (`failed: 'composed-message'`). New `AgentInput.messageFrom: 'person' | 'composed'` for code that composes runners by hand (any other value is refused at `run()`).

Served only under the arm: the `from` property on a RULED tool's `_findings` (every other tool keeps the base), one line of the findings instruction (`FINDINGS_SOURCES_LINE`) — measured on 2026-09-27 at +617 characters on the ruled tool's schema and +447 on the system prompt, an unruled tool +0. Refused at build without the inputs layer. Off (the default): no property, no line, no check, no new key — every earlier run is byte-identical (the 25 references under `test/core/tools/reference/` did not move; `agent-arguments-sources` pins the armed run). Nothing is claimed about the model: whether the arm pays for its tokens is measured by the inputs bench's step-5 rule, registered before its first paid call.

Surfaces that widen, named: `ArgumentRow` rows now carry `claimed`, `matched`, `quote`, `reading`, `earlier`, `result`, `setAside`, `argumentsFrom`, `appSource`, `coincides`, `malformed`, `failed` and `asked: 'unverified'` (the fields were declared; they are now written); `AssessmentReason` gains `argument-read` and `value-contingent`, `AssessmentCheck` gains `argument-sources` (a reader that switches over every member must skip one it does not know); `FindingsDeclaration` gains `from`; `AgentState` gains `userMessageFrom`; `HonestyLayers` gains `argumentSources`; `ArgumentResolution` gains `quoted`.
