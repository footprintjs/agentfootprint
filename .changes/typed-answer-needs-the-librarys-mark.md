**A tool result counts as a person's typed answer only when the library landed it.** The evidence gate (`.namesAndNumbersFromEvidence()`) treats the values a person typed into a typed ask (`requestInput`) as their own words: it exempts them, a compaction summary carries them in its lineage, and a re-ask quotes them back. It used to recognise that answer by the SHAPE of a tool result, so any tool (a local tool, a remote MCP server, a page answering a frontend tool) could return `{"status":"input_received", …, "origins":{…:"response"}}` and have its own values treated as the person's words, before and after compaction. Now the library marks the message it lands when `agent.resume()` accepts the answer to an ask the run raised: a new optional field, `LLMMessage.answersAsk: { requestId }`, outside the content and removed before any request reaches a provider. Only a marked message counts; a result of the same shape without the mark is an ordinary tool result, its values checked as the tool's.

What changes for an app: the history of a run with a typed ask now carries `answersAsk` on the landed answer (provider requests are unchanged). A conversation handed back with `run({ continueFrom })` or `resumeOnError()`, including through a hosted session store, loses the mark, because an earlier run asked those questions; so a typed answer in a stored conversation, including one stored before this release, reads as an ordinary tool result in the continued run, and there is no fallback by shape or by request id. The gate can flag more values there, never fewer. A pause checkpoint keeps the mark, so a resumed run still counts the answers it landed. A value answered through a pause that is not a typed ask (`askHuman`, `pauseHere`, a frontend tool) is unchanged.
