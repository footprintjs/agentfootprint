**Composition members run for the run that mounted them — never for a shared bucket.** A composition (`Sequence`, `Parallel`, `Conditional`, `Loop`, `workflow`, `graph`, and every pattern built from them) runs each member's chart in its own executor, so a member Agent's `run()` never runs — and its memory namespace, its tools' `ctx.identity` and `ctx.runId` were read off the member instance, which every run of the composition shares. An instance never run on its own held the placeholder conversation `'pending'`, so every user of a composition read and wrote ONE memory (one user's earlier messages reached another user's model); an instance that had run on its own handed its last caller's identity to the next composition run's tools.

Now the outermost composition run builds one run record — the caller's identity, passed as `run({ message, identity })` (or `input.identity` for `workflow` and `graph`), and that run's own id — and every composition hands it to each member that reads it, at any depth of nesting. A member Agent runs under the caller's identity, or that run's own `{ conversationId: runId }` (recorded `runIdentitySource: 'composition'`), and its tools read `ctx.identity` / `ctx.runId` from the run. An Agent tells its own run from a mount by the scope it was given, so two overlapping runs cannot be confused, and the agent's own runs record exactly what they did before. An Agent mounted in a chart you build yourself must be handed `identity` by your input mapper: one that no run reaches is refused with `MemberIdentityError`, never run under its instance's last run or a placeholder. Runners other than an Agent or a composition are handed exactly the input they were before.
