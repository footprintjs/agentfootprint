---
type: breaking
---
**A person's decision now answers ONE paused request, once, for the exact call they were shown.** A consent gate (a tool's `checkIn`, a middleware's `ask`) mints a request id when it pauses — `CheckInRequest.id`, `MiddlewareAsk.id` — bound to the call that runs on approval: the tool, its arguments, the call id, the served party and, for an ask, where the chain resumes. `checkInApproved({ request, by })` / `checkInDeclined({ request, by })` copy it into the new `CheckInDecision.requestId`, and a resume refuses, with the new `ResumeDecisionError` (`code: 'ERR_RESUME_DECISION'`, `reason`), a decision that:

- names no request (`'no-request'`) — built by an older release, or by hand;
- answers a pause that recorded none (`'request-not-recorded'`) — a checkpoint written before this release;
- names another request (`'other-request'`) — another conversation's, an earlier pause of the same run, a parallel sibling's;
- names this request for a call the checkpoint no longer holds (`'call-changed'`) — its arguments, tool, call id, party, chain position or the rules recorded after the ask were altered after the ask;
- answers a middleware ask on an agent whose `toolMiddleware` chain, from the asking link on, is not the one the person was asked under (`'chain-changed'`) — a later rule removed, added, renamed or moved by a redeploy is never skipped;
- was already used by a resume (`'already-answered'`) — approved or declined.

On approval the tool runs with a detached copy of exactly the arguments the person was shown (before, a resumed tool was handed a live view of the run's state, which later read the next pause's call). For a middleware ask, the links after the asking one still run and may still deny, but a link that hands back **different arguments** — a new object, or its copy edited in place — no longer has them run (the arguments are held to the request itself, and the tool runs on a fresh copy no link holds): the call is refused, the model reads why, and the record keeps the rewrite and a deny row. An ask whose arguments cannot be bound is recorded as that refusal, never as an `ask` row nobody answered.

Before this, any decision-shaped object answered any consent pause: a duplicate "approve" that arrived after the first had resumed the run approved the NEXT refund nobody was shown, a stored checkpoint whose arguments were edited after the ask still ran on the person's yes, and resuming the same checkpoint twice ran the tool twice. The tool never runs on a refusal. An agent's own `resume()` refuses all but `'already-answered'` before anything moves; a request is spent where its decision is used, still before the tool — which is also where a composition's nested agents (`Sequence`, `Parallel`, …) are held to the rule, since a composition resumes them directly. A nested agent's consent pause answered with something that is not a decision is no longer turned into an invented `by: 'unknown'` decline: it is refused (`DecisionRequiredError`), the same as on an agent's own `resume()`.

Answered requests are spent in a `DecisionLedger`, and **"once" holds per ledger**. By default every agent that names none shares one ledger in this process's memory, so a server that builds an agent per request, a pool that rebuilds an evicted instance, or a composition's nested agents still answer each request once — in this process. It does not survive a restart and no other process sees it: when more than one process can resume the same paused run, give every agent that can resume it one ledger whose `spend(requestId)` is atomic in a store they all reach (`Agent.create({ decisionLedger })`). A refusal for an answered request says what that resume knows — it ran nothing, and whether the earlier resume finished, so whether the call ran, is not known there. `standingAgent` also marks a stored pause answered (`PausedRun.answered`) when a resume fails after using its decision (the tool ran, the next model call failed): a retry, a rebuilt instance, a restart or another host on the same store is refused with 409, and the next message continues the conversation from that run's own history, any call it left open settled as unknown (under findings admission, `toolResultOrigin: 'outcome-unknown'`). `checkin.decision` events and `CheckInRecorder` decisions carry `requestId`, so the record joins each decision to the request it answered. A gated call whose arguments are not plain JSON (a `Date`, a `Map`, a non-finite number) cannot be bound and is refused at the gate — the tool does not run, nobody is asked, and the model reads why. Hosting doors answer `ERR_RESUME_DECISION` with 409; over AG-UI the page needs no change — the interrupt it answers is matched to the kept pause and the adapter names that pause's request.

Migration: build every decision from the request the person was shown — `checkInApproved({ request: outcome.checkIn, by })` for a check-in, `checkInApproved({ request: outcome.ask, by })` for a middleware ask; on a hosted door, `request: pending.checkIn` / `pending.ask` from the `PendingAsk` the host replied with, sent as `decision`. A client that builds the decision JSON by hand adds `requestId: pending.checkIn.id` (or `pending.ask.id`). A plain `askHuman()` / `pauseHere()` pause is unchanged — its answer is a value. Consent-gate checkpoints written by an earlier release cannot be answered (`'request-not-recorded'`): drain them before upgrading, or abandon them and ask again. If more than one process can resume one paused run, pass a shared `decisionLedger`.
