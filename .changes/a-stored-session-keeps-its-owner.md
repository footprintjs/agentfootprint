**A stored conversation keeps its owner: a save in the middle of a run, an anonymous turn and a reloaded question can no longer hand it to somebody else.**

- **A save in the middle of a run carries the owner.** With `durability: 'sync'` or `'async'`, every save the run made before its end stored the conversation without `identity`. A turn that failed after such a save left a row that named nobody: its owner was then refused at a door with an identity verifier, and an anonymous caller at a door built with `allowAnonymous` was served it, so the model read the owner's earlier messages. A different user's turn at a door with no verifier had the same effect: its save replaced the owner's conversation with an ownerless one before the store refused the turn's final write. Every save now carries the identity the finished conversation carries. The store's ownership refusal is no longer wrapped as "the session store did not accept this run's progress": under `'sync'` or `'async'`, a turn by a different user now fails with `ERR_SESSION_OWNERSHIP_CONFLICT`, as it does under `'exit'`, and nothing of it is stored.
- **Reloading a waiting question follows the rule an answer follows.** At a door with no identity verifier, `session-pending` served the question, with the request id an answer quotes and the person's own message, to any caller, including one naming a different user, whose answer the store would refuse. That caller now gets `ERR_SESSION_NOT_FOUND`. A caller who names nobody is still served: at a door with no verifier the session id is the key, as before. At a verifying door nothing changes.
- **`agentEngineSessions`: the first person who signs a conversation stays its owner.** A conversation whose first turn was anonymous kept its owner only inside its newest envelope, so one anonymous turn erased it and the next signer was accepted. The owner is now kept in its own session state key, `agentfootprint.owner`: an anonymous first turn writes it empty, the first signed turn fills it in, an anonymous turn never touches it, and a different signer is refused with `ERR_SESSION_OWNERSHIP_CONFLICT`. A reader older than this release reads only the envelope and id keys and ignores the new one.
- **`agentEngineSessions`: the session list hands out only ids that open their conversation.** A session saved before the store carried the caller's own id was listed under its resource id. For an id the store had to rewrite (capital letters, punctuation, more than 63 characters), that resource id has opened nothing since the store's id rule stopped passing its own rewritten form through unchanged. Such a row is now listed under its resource id only when that id still opens it, or under the id its conversation was stored under when that id addresses exactly that row; otherwise it is left out of the list. The earlier release note that said this fallback works "exactly as before" was wrong for those rows.

What an app will notice, every case that is now refused:

- At any door, under `'sync'` or `'async'`: a turn by a user other than the conversation's owner fails with `ERR_SESSION_OWNERSHIP_CONFLICT` instead of the store-progress error, and the stored conversation is unchanged.
- At a door with no verifier: `session-pending` for a session owned by another user than the one the request names answers `ERR_SESSION_NOT_FOUND`.
- `agentEngineSessions`, a session stored before this release, under the anonymous placeholder, whose conversation names nobody: a signed turn on it is refused with `ERR_SESSION_NOT_FOUND`, at every door and for every signed user, because the record cannot say whether somebody signed for it and was erased. Anonymous turns on it are stored as before. Continue such a conversation under a new session id.
- `agentEngineSessions`, a session stored before the store carried the caller's own id, whose resource id was rewritten and whose conversation does not name an id that addresses it: it no longer appears in `listByUser` (it could not be opened from the list before either). Open it by its original id, or save it once under that id.
- Not changed: rows that already lost their owner to the mid-run save before this release stay ownerless, and the stored format has no mark that tells them apart from a conversation that began anonymously. At a verifying door they are still refused to every signed caller; at a verifying door with `allowAnonymous` an anonymous caller can still open them.
