**A missed name is a named miss over the names a tool read: `absent({ what, among })`.** A lookup that checks a name against one known list (an inventory export, a share table) and finds nothing now declares that list — `among: { argument, source, measuredAt, count, names?, visible?: 'caller' }` — instead of wording the miss itself. The library composes the names facet the tool searched into `checked`, adds a gap the author cannot remove to `not_checked` (`names outside <source>`, a scope gap that bears on the source; only `authoritative: { why }` drops it), and composes `provenance` from the source and the time it was read. Only when the tool read the list under the caller's own identity (`visible: 'caller'`, no default) does the model see `known_names`: the count and the 20 names nearest the one asked for, in the evidence gate's spelling. Names outside one plain printable line or over 128 characters are dropped and counted; a looked-for value over 128 characters or a list over 10,000 names serves the count alone. The names are never part of the result: `absent()` keeps them on a library-owned channel keyed by the envelope it returns, and the framework attaches them only to the message the model reads, after every `onToolResult` rule, result placement and `maxToolResultChars` — so the rules, `stream.tool_end`, `tools.absent`, the tool-call ledger and the `coverageDeclared` row never see them, whatever a rule does to the result, and a result a rule denies is served none. They live in the conversation the model read. A count that disagrees with the names is refused (`names-count-mismatch`). Why: in a registered study, a refusal that said "a wrong identifier, not missing data" made models tell users the thing did not exist, when the tool had searched one list. A well-formed unknown value is an absence, never a refusal; a value the input schema refuses is still refused before the call runs.

`check:semantics` gains three overclaim rules: `refusal-asserts-absence` (a refusal sample — the new catalog field `refusals` — that carries an absence, `known_names`, or a sentence saying what does not exist or that the input is wrong), `absence-asserts-wrongness` (an absence whose words call the input wrong) and `authoritative-names` (every `authoritative` use, for review). They are warnings, and only for samples that use the new fields, so an app that uses none of them sees no new finding; `--strict` reports the first two as errors, and `--rules=overclaim` (`checkSemantics(entries, { rules: ['overclaim'] })`) makes them errors over every sample. The library's own refusal sentences are pinned by test to carry no absence and no non-existence claim. Internally, the one spelling normaliser moved from `tools/` to `lib/` so the coverage mint can rank names by it.
