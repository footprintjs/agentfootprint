**A missed name is a named miss over the names a tool read: `absent({ what, among })`.** A lookup that checks a name against one known list (an inventory export, a share table) and finds nothing now declares that list — `among: { argument, source, measuredAt, count, names?, partial?, authoritative? }` — instead of wording the miss itself. The library composes the names facet the tool searched into `checked` (with "names as of <measuredAt>" when `measuredAt` is an ISO 8601 instant), adds a gap the author cannot remove to `not_checked` — `names outside <source>`, a scope gap that bears on the source, which only `authoritative: { why }` drops; a `partial: true` read also gets `not every name in <source> was read`, which nothing removes — and composes `provenance` from the source and the time it was read. The gap holds where `among` is declared; a plain `absent({ what })` or a thrown refusal bypasses it. `count`, `partial` and `authoritative.why` are the tool's claims, not verified. `names` is read only to check `count` (`names-count-mismatch`): no name is served to the model or written to an event or the record — serving "did you mean?" names waits on a measurement. Why: in a registered study, a refusal that said "a wrong identifier, not missing data" made models tell users the thing did not exist, when the tool had searched one list. A well-formed unknown value is an absence, never a refusal; a value the input schema refuses is still refused before the call runs.

`check:semantics` gains three overclaim rules: `refusal-asserts-absence` (a refusal sample — the new catalog field `refusals`, as text, a value, or `{ text, argument?, value? }` — that carries an absence, or a sentence about what was looked up saying it does not exist or that the input is wrong), `absence-asserts-wrongness` (an absence sentence that calls the looked-up value wrong) and `authoritative-names` (every `authoritative` use, for review). They fire only on a sentence that names the looked-up argument or value; a format, range, permission or transport sentence exempts a wrongness phrase but never a non-existence one; they are warnings, and only for samples that use the new fields, so an app that uses none of them sees no new finding; `--strict` reports the first two as errors, and `--rules=overclaim` (`checkSemantics(entries, { rules: ['overclaim'] })`) makes them errors over every sample. The library's own refusal sentences are pinned by test to carry no absence and no non-existence claim. Internally, the one spelling normaliser moved from `tools/` to `lib/`, a leaf every layer can read.
