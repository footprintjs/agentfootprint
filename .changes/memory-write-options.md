**Memory write options: skip long-term extraction, and a namespace per tenant.** The `MemoryStore` port's writes (`put`, `putMany`, `putIfVersion`) take an optional third argument with two vendor-neutral options, and `defineMemory({ writeOptions })` applies them to every write a memory makes:

- `extraction: 'skip'` — store the entry, but keep it out of the service's long-term extraction (no fact, summary or preference is derived from it);
- `namespaceScope` — the values the service puts into the namespaces its derived records are filed under: `(identity) => ({ tenantid: … })` for one per tenant, or a fixed object for a single-tenant deployment. A scope that comes back empty or malformed refuses the write instead of sending it without one.

`AgentCoreStore` honours both, as `CreateEvent`'s own fields: `extractionMode: 'SKIP'` and `extractionConfig.namespaceVariables`. It does so only when they can reach AgentCore intact — an injected client must declare `forwardsWriteOptions: true`, and the installed `@aws-sdk/client-bedrock-agentcore` must model both fields (an older serializer drops them silently) — and it checks the variables against AgentCore's documented domain before sending, refusing by variable name without quoting the value. `agentCoreNamespaceValue(tenant)` maps a tenant id into AgentCore's narrow alphabet one-to-one (it refuses rather than truncates), and `searchNamespace` now receives the identity, so a search can read the same per-tenant namespace the writes were filed under.

**`AgentCoreStore.search()` now reads only its own namespace.** AgentCore's `namespace` filter is a string prefix, so `/tenants/v1` also matched `/tenants/v12`. Results are now kept only when one of the record's `namespaces` (the SDK's `MemoryRecordSummary.namespaces`, which the adapter previously did not read) is the namespace asked for or lies under it, on whole path segments; a record that reports no namespace is dropped, because it cannot be shown to belong. An actor id can contain `/` (its escape is `/` plus four hex digits), so one actor's id can extend another's by whole segments (`bob@x.com.au` after `bob@x.com`): when the namespace searched ends with `{actorId}`, a record filed under a continuation that starts with four uppercase hex digits is dropped too. A namespace containing `*` is refused by name, since a wildcard cannot be checked for ownership. A custom `AgentCoreLikeClient.retrieveRecords` must now report `namespaces` (or `namespace`) on each record.

Every other store refuses the options **by name** (`UnsupportedMemoryWriteOptionError`) before writing anything, never ignoring them: a dropped namespace would file one tenant's derived records where another's are read. A store declares what it honours in the new `MemoryStore.writeOptions`, `defineMemory` checks it before the first turn, and a third-party store can refuse in the same words with `refuseUnhonouredWriteOptions`. Writes without options are unchanged.
