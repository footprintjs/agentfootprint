**Observe negative claims in ordinary agent answers.** `.negativeClaims({ prose: true })` compares data-anchored prose claims with native tool observations without requiring an output schema, citation field or answer validator. If the grammar detects an eligible negative and no dispatched native read is recorded for the current turn, it files one `no-read` note per answer. Earlier-turn reads do not suppress it; a recorded dispatched read does, even if failed or kept out. This is a presence check, not proof that no read occurred or that recorded evidence is usable. The observer filters the exact normalized ordinary clauses "None.", "No action is needed." and "Tests: 0 failed." so they produce no `no-read` warning; added words or separate negative clauses remain eligible. It preserves the answer and normal streaming, adds no correction call, and never withholds or verifies prose. Current-turn findings make the answer assessment not-sure; silence from the heuristic does not mean verified. App answer validation remains independent, and the prose-only arm refuses `.outputFallback()` because that path can replace an answer after observation.

**Subscribe to bounded prose warnings.** `agentfootprint.findings.negative_claim` emits once per claim or unread-unit finding, with locations, checker codes, phrase-pack identity and native result references, never answer text or tool values. App literal phrases can extend the observer within fixed limits. Code, recognized unsupported languages and exceeded size or shared work budgets produce explicit notes; exhaustion replaces partial findings with one input-limit note. The prior detector failed every free-replay benchmark gate. The revised, data-anchored path remains unmeasured and can miss claims or flag correct ones; `strictProse` and `enforceProse` stay unavailable.
