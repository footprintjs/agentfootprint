**`.outputSchema(parser, { strategy: 'native' })` — the provider's own structured output.** Asking for JSON in the system prompt is not enforcement: a Claude Haiku 4.5 run answered with prose around a fenced JSON block, and the schema correctly rejected it. The new `'native'` strategy sends the schema as Anthropic's `output_config.format`, so the text answer is decoded under it, while the agent keeps its tools (the model may still call one first). `anthropic()` and `browserAnthropic()` declare it for the models Anthropic lists (Haiku 4.5, Sonnet 4.5, Opus 4.5 and later; an unknown id is read as the newest generation), and anything else is refused by name at run start with `UnsupportedNativeOutputError` — never quietly downgraded to `'instruct'`. The schema sent is an API-compatible copy (objects closed, constraints the API does not take moved into the description) and your parser still judges every answer, so nothing is weakened; a schema the API cannot express is refused at build, naming the node. A `stop_reason` of `'refusal'` or `'max_tokens'` fails the attempt by name (`OutputAttempt.stopReason`) even when the text parses. With `.findings()` armed, the format allows the reserved `_findings` key so answer standings keep working. `answerGuarantee` reads `'native'`. Requests without the strategy are byte-identical.
