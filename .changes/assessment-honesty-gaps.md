- **`declaration-overclaimed` now names the call whose refusal said more than it read.** Under `.negativeClaims()`, a refused call whose refusal says something "does not exist" makes the answer "not sure" with `declaration-overclaimed`, and its `source` (on `agent.assessment()` and `assessAnswer(recording)`) now lists that tool's calls of the turn: `{ kind: 'calls', calls: [{ toolCallId: 'c1', toolName: 'read_incidents' }] }`. Before, the reason fired but its source read `{ calls: [], unnamed: 1 }` on every real run, because the check row on `agent.answerValidation()` lost the tool's name on its way there. That row now keeps it: a `.negativeClaims()` row carries `tools` (the new optional `AnswerCheck.tools`, names only) beside its code in `reason`, the two fields the fold reads.
- **`assessAnswer()` no longer throws on a sparse list in an in-memory record.** A conflict's readings, a contingent value's carriers or an answer check's `tools` with a hole in them (an index no value was ever assigned to, which a live or host-built snapshot can hold and a saved recording spells `null`) made `assessAnswer({ snapshot })` throw a `TypeError`, or, in `tools`, silently drop the hole. Each list is now read by index: a hole is one entry that names no call, counted in the reason's `source.unnamed`.
- **A conflict filed in this turn makes the answer "not sure" even when its readings carry no call ids.** With an honesty layer armed (its findings rows carry their conversation turn), a conflict row stamped with this turn whose readings named no call left `assessAnswer()` and `agent.assessment()` at "consistent with the record", with no `sources-conflict` reason. It now fires, and its `source` counts the readings the record cannot name in `unnamed`. A row stamped with this turn whose readings all name earlier calls is still not this turn's, and an unstamped conflict is still placed in this turn only by a reading that names one of the turn's calls, so an earlier turn's conflict whose ids are gone is never attached to today's answer.
- **The answer account's "How sure" row says a declared absence is what the tool reported.** For a call whose tool declared that nothing matched, the row read "The call found nothing.", which reads as established absence. It now reads "The call reported no matching results.", the attribution the standing line already uses. The template is `howSure.outcome.nothing@2`, and the account's template set (`AnswerAccount.templates.version`) is now 13.
