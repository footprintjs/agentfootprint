**`agentfootprint/time` — the time layer's own period conversion, for an app outside a run.** An app that previews what a tool would read for the person's window, or builds a call itself, used to keep its own copy of the conversion, and a copy drifts the first time the fill's rules change. The door leads with `convertForTool`, the question the run asks of each tool: give it the window, the tool's forms (`sugarForms(period)`), the tool's `period` as its facts, and a clock whose step is `granularityMsOf(period)`. It answers `{ conversion }` (exact, else the wider read with `sent` and `extra`, marked `partlyBeyondRetention` when the window is only partly older than `retention`) or `{ refused }` with a `TimeRefusal` code: a fact the window breaks, `multi-day`, or `no-form-holds` (which covers a look-back longer than `maxRange`). The steps ship too, for a caller that needs one alone: `convertExact`, `convertWidened` (ask it only after `convertExact` finds nothing; its fourth argument is `widestMsOf(period)`) and `periodFactProblem`. Their types ship with them: `ToolConversion`, `TimeRefusal`, `PeriodShapes`, `ConvertContext`, `WindowToConvert`, `Conversion`, `WidenedConversion` and `PeriodFactProblem`. They are the same function objects the run calls, so a preview built on `convertForTool` shows what the run sends or refuses. They need no run, write no record and do not need `.time()`. They live on their own door because they are part of the layer's run-time half: the main barrel still keeps that half off a plain agent's import graph, and nothing a plain agent loads changes.
