**A source's held span is served in the person's zone; a resumed answer's account reads its routing from the record.**

Under `.time()`, when a call's source holds none or only part of the time it asked about (period verdict `not-held` / `partly-held`), the `period` row now carries `held { queried, held }` and the served time line states it for the model in the person's zone — "pscale_client_health asked about 2026-09-30 06:00:00–11:59:50 America/Los_Angeles (UTC-07:00); its source holds 2026-10-01 09:22:44.300–10:02:44.300 America/Los_Angeles (UTC-07:00), which covers none of that time" — through the same renderer as the person's `Period:` line. The model no longer converts a source's UTC instants itself (a demo answer said "9:22 AM–5:02 PM Pacific" for a 16:22–17:02 UTC span). `timeFormsOf({ held })` spells those times as the library's (`derived`), so an answer that repeats them is filed `time-derived` instead of "not traced"; a time the line does not name is still flagged. Without `.time()` nothing changes.

"Explain this answer" (`accountForAnswer`) on a resumed leg now reads the routing verdict from the state the run paused with — RouteTurn commits `turnRoute` and the scorer's `entryScores` before the loop — so "It understood" names the routing (marked "before the pause — read from the state this record holds") and the decided-delivered check runs, instead of "The routing happened before the pause and is not in this record". That sentence remains only for a record whose state holds no verdict. The "Anything wrong" line about the part before the pause no longer names the routing as lost when it was read (new template `wrong.beforePause.held.events`; template set version 9), and a call the record shows presenting an artifact (`artifacts.presented`) is no longer judged by the empty-results check — its result is a receipt, not data. "Show me" shows the `turnRoute` and `entryScores` leaves the verdict is read from.
