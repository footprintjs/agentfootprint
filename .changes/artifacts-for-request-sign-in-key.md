**`handle.artifactsForRequest` now knows a person signed in by the sign-in cookie.** It verified a request without the sign-in key, so everyone signed in through the cookie door (`local-password`, `directory-password`, browser OIDC sign-in) was answered `'unverified'` — only bearer, proxy and open doors could bind. `ArtifactsForRequestInput` gains an optional `signInKey`, and the seam now verifies exactly as the turn door does (`verifyRequestIdentity` with the key): the owner binds, another signed-in person gets `'not-found'`, an ended or expired sign-in is `'unverified'` (`expired`), a sign-in store outage is `'unavailable'`, and a key together with a bearer token is `'unverified'` (`two-credentials`). Its fields are `HostRequest`'s own, so inside a handler pass the request itself — `handle.artifactsForRequest(request)` — and nothing can be left behind; on an app's own route take the cookie off with `readSignIn` and pass only its key. The old input shape is unchanged. A filing made through the seam still carries no `origin`: the call runs nothing, so there is no run id to vouch for.
