**A tool declares what its search is made of, and the library composes each call's coverage from the arguments the call ran with — `Tool.search`.** A model turns "the tool found nothing" into "it does not exist", and a hand-written `checked` list says the same thing for every call. Now `defineTool({ search })` classifies every input argument by role (`population`, `filter`, `period`, `source`, `query`, `match`, `cap`, `page`, `inert`), names each default (`whenOmitted`: a value, or `{ any: true }`), each qualifier the tool always applies (`fixed`), each blind spot with the facet it bears on (`gaps`), a server cap or a credential-limited read (`limits.cap`, `limits.byCredential`), an approximate ranking (`ranking: 'approximate'`) and whether a call is complete within its arguments (`complete`). The result says `absent({ what, checked: 'declared' })` (or `coverage(rows, { checked: 'declared' })`), and the dispatch funnel composes the rest from the call: a sent value, a default, a fixed qualifier, the declared or sent source, an identity-filled argument by reference. Every argument none of those covers is a gap — an empty list included; a cap, a page, a `partial` outcome or an approximate ranking bears on completeness; a free-text query and a credential-limited read bear on the population. So composition can only under-claim relative to a true declaration: a declaration that misdescribes its query is the trusted base, said out loud. A relative window resolves at the moment the call ran. The model reads the composed absence — typed items, the gaps, a note that a default may have applied, and a long list as its count and first few values — never `complete`, which rides the record. The `coverageDeclared` row keeps every value at a library-minted address (`resultId`, and the short `handle`), never a provider's call id; events carry constants and references, never a composed value. A declaration that arrived over MCP or from a ToolProvider composes rows marked `composed: 'remote'`, which establish nothing. `absent()` and `describedResult()` also take `resolved` (the entity a value resolved to — it binds only the value sent, under the one case rule now in `lib/normalize.ts`) and `paging` (`{ next: null }` says there is no next page). A malformed declaration, or text that would reach a statement and is multi-line, over 120 characters or instructing, is refused at `defineTool` and again at the agent's registration, so a hand-built tool cannot skip it. `effects: 'read'`, written in `defineTool` on a local tool, records that the tool changes nothing; a remote tool carrying it is refused. A tool with no `search` composes nothing and its run is byte-identical; `absent({ checked: 'declared' })` from such a tool is the call's error. `check:semantics` lists each search's `source.said` words and any `said-overlap` as warnings. An envelope carrying `resolved` or `paging` is refused whole by an older reader, so upgrade readers before tools.
