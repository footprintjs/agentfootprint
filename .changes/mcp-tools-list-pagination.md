**`mcpClient` now reads every page of a server's tool list, and says so when it cannot.** `tools()` and `refresh()` read only the first page of `tools/list`, so a server that paginates its catalogue was cut short in silence: the agent was offered part of it and nothing said so. The client now follows `nextCursor` until a page carries none, for at most 100 pages. A list that does not end within them, or a page that names a cursor the listing already sent (a loop), is no longer returned cut short: the call rejects with the new `McpToolListIncompleteError` (`agentfootprint/providers`), whose `reason` is `'page-limit'` or `'cursor-repeated'`, whose `pages` counts the pages read and whose `tools` holds what was listed, callable, for a caller that chooses to use an incomplete list. The client's `signal` rides every page, and no page is asked for once it has fired. A server that answers in one page gets exactly the request it got before. `McpConnection.listTools` now takes an optional `{ cursor }` and may return `nextCursor`, as the MCP SDK's own `Client` already does; a connection that never pages is unaffected.
