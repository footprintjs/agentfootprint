**A recording saved in parts keeps each sub-flow's input and output with that sub-flow, so the largest runs open at the root.** In a run saved with `artifacts: { recordings: { layout: 'parts' } }`, almost all of the base part was one field: the `payload` of every `subflow.entry` and `subflow.exit` boundary event, a second copy of what each invocation's own part already holds (17.6 MB of a 28.8 MB base in one measured run of 19 model calls). The writer now files index format 2 (`agentfootprint.recording.index.v2`, with `…part.v2` parts): such a payload moves to its invocation's part, only on proof (the boundary rows hold exactly one entry and at most one exit with that `runtimeStageId` and its `subflowId`, `payload` is the event's last key, and the invocation has a part; anything else stays in the base and is counted). A payload whose JSON text equals the result's own value is not stored again (`'same'`); any other is stored beside the result (`'stored'`), as under a redaction policy that selects a seeded key, a nested name rule or an empty seed. The base row says so: a moved event carries `payloadWith: 'invocation'` in place of `payload`, and its row's `meta.subflowPayloads` is `'with-invocation'`. `openSavedRecording(…).readInvocation(key)` returns the invocation's `payloads` (`{ entry?, exit? }`, each `{ status: 'ready', value }` or `{ status: 'unavailable', reason }`) beside its result; `readRoot` returns the base as stored; `readWhole` puts every payload back (the boundary row is the same JSON text), charges the bytes it restores against `maxBytes`, and `sizes.restoredBytes` reports them. `buildStepGraphFromEvents` carries the mark: a step or slot gets `entryPayloadWith` / `exitPayloadWith: 'invocation'` instead of a value, so "with the invocation" is never shown as "none recorded". The reader still opens index format 1 (filed by 18.2 and 18.3) and whole recordings exactly as before, and answers an index of a format it does not know with the new reason `unsupported-format`.

Migration: Upgrade every reader before any writer files a new recording: an 18.2 or 18.3 reader refuses an index-format-2 recording at open as `invalid-index`. A viewer that draws sub-flow inputs and outputs from the root's boundary events must, for an event or step that carries `payloadWith` / `entryPayloadWith` / `exitPayloadWith: 'invocation'`, read that invocation (`readInvocation(runtimeStageId)` and its `payloads`; a host passes the reply's `payloads` through) or say the value is not loaded. Code that switches over `SavedRecordingUnavailable['reason']` handles `'unsupported-format'`. A host that sizes a whole read from `sizes.storedBytes` uses `sizes.restoredBytes`.
