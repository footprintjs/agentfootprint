**A tool turn that changes its own context is refused by name, before the request is sent.** On Claude models that accept signed reasoning only under the system prompt, tool list and earlier messages it was written under (Haiku, Sonnet and Opus 5.5, Fable 5.1 and 5.2, Mythos 5.1 and 5.2), loading a skill mid-turn, an instruction or fact whose `activeWhen` reads a tool result, a tool provider whose list moves, or a skill graph step stopped the run with the adapter's `UnsafeThinkingReplayError: prefix-changed, message 1`, which named none of them. The run now stops one step earlier with `ContextChangedError` (from `agentfootprint/providers`): a fixed sentence plus the slot and the skill, injection or tool that changed, never their content. It is a request refusal, so it is not retried or sent to a fallback. It is raised only on a model known to bind its reasoning. These models think without `.thinking()`, so the check does not depend on it. A run that does not change its context mid-turn, and every model that does not bind its reasoning, sends exactly what it sent before.

A change that is not refused (after a finished turn, the final wrap-up call that withdraws the tools, or on a model whose binding is unknown) is recorded on `agentfootprint.stream.llm_start` as `contextChange`, by name. A conversation continued from an earlier run is recorded `unchecked`.

Providers answer per model with the new optional `LLMProvider.thinkingBinding`, read with `thinkingBindingOf(provider, model)`: `bound`, `unbound` or `unknown`, and who said so. The Anthropic, browser Anthropic and InvokeModel gateway adapters answer from their model table, and answer `unknown` for an id the table cannot place (an application inference profile, a gateway alias, a model newer than the table). On an `unknown` model a changed tool turn is sent as before and recorded with `binding: 'unknown'`, because such an id may serve an older model whose thinking is not bound. State the model behind such an id with the adapters' new `thinkingBinding` option (`(id) => 'bound' | 'unbound' | undefined`); the record then says `by: 'app'`. `withRetry` and `withCircuitBreaker` forward the answer, and `withFallback` takes the stricter side. The table gains `claude-fable-5-2` and `claude-mythos-5-2`, and marks `claude-mythos-5-1` as bound: the adapter's replay check applies to them, and a forced tool choice on Fable 5.2 or Mythos 5.2 is refused before sending, as Anthropic documents the API refusing it.

Until the agent delivers such changes as appended messages, keep a skill's tools listed from the first request and its body in the `read_skill` result (`surfaceMode: 'tool-only'`).
