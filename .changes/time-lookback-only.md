**A past window on a look-back-only tool is read wider and recorded so, or refused by name — never silently read as the tool's default.** Under `.time()`, three gaps are closed. **The call that asked is now recorded like any fill:** when the person confirms (or types) the window in the time ask, each call it filled gains a `call-window` row `how: 'filled'`, `person.source: 'answered'`, with `sent` and `differs.extra` when the tool reads wider (a look-back from now covering "yesterday 8 AM to 9 AM"); the tool now receives `ctx.time.asked`, the clock at dispatch can see its look-back, and the result checks report the over-inclusion ("search_logs read more than was asked") — before, that call kept only its `not-filled` row and the wider read was on no record. **A window no form can read is refused:** a window still running sent to a look-back-only tool, or one whose covering look-back is longer than the tool's `maxRange`, used to fall back to the tool's own rule, so an `assume: '1h'` read the last hour instead; it is now refused before dispatch with the new reason `no-form-holds` (`TIME_REFUSALS`), a reading the tool cannot reach is no longer offered in the confirmation, and a look-back exactly `maxRange` long is read. Under the reader, the next request's time line turns a refusal of the person's window into what the answer states ("client_activity was not run for “10/20/26”: … So the answer tells the person that client_activity could not read that time …") instead of naming the same refused call as the next step. **A start and end the person gave are one window:** answered as two fields (`From when?`, `Until when?`), a pair that breaks the tool's `direction`, `retention` or `maxRange` together is asked again naming the fact, then refused — with or without the reader; before, a future pair ran against a tool whose source holds only the past. Also: a checkpoint holding a refusal of an open reading (no range) now passes the checkpoint check. Without `.time()` nothing changes.
