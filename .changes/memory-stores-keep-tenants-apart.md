**Memory stores keep tenants and conversations apart however a scope value is spelled or typed.** Two fixes, no change to any public name or type.

- **`memoryBankStore` refuses a scope part that is not text.** When an app's `scopeFor` returned a part whose value was not a string (a numeric tenant id from request data, in plain JavaScript or through a value typed `any`) or whose key was empty, that part was silently dropped. The scope then became wider than the app asked for, and tenants that differed only in that part listed, read, overwrote and erased each other's memories. Every operation (`list`, `search`, `get`, `put`, `putMany`, `delete`, `forget`; an empty `putMany` stays a no-op) now throws a `TypeError` naming the key (never the value) before anything reaches the service. **What you will notice:** a `scopeFor` that returns `null`, `undefined`, a number, a boolean, an object or an empty key now fails loudly at its first memory call, for example `memoryBankStore: 'scopeFor' returned scope part 'tenant', whose value is not text, for conversation 'c1'.` Convert the value to text in `scopeFor`. A `scopeFor` that returns only text sees no change. Memories already written under a narrowed scope keep that scope, because Memory Bank scope is immutable: a corrected `scopeFor` does not see them, and they stay readable to anyone whose scope is the narrowed one until you remove them.
- **`s3VectorsStore` no longer lists or erases one conversation's memory through another's.** A conversation id may contain `#`, and the store's keys are `<namespace>#<id>`, so the key prefix of conversation `c` was also a prefix of every key of conversation `c#x` (same tenant and person). `list` and `forget` selected rows by that prefix, so listing `c` showed `c#x`'s entries and erasing `c` erased them. Both now keep a row only when its stored namespace (the `ns` metadata every row this store writes carries) is the conversation's own; no stored data changes. **What you will notice:** for such ids, `list` and `forget` stop reaching the other conversation; `forget` now asks ListVectors for metadata. Rows in the index that carry no `ns` metadata (not written by this store) are no longer erased by `forget`. Still open, and named in the store's docs: when the entry ids also line up (`c` with entry `x#y`, `c#x` with entry `y`), the two writes share one key and the later replaces the earlier; closing that re-keys stored vectors and is left for a major version.
