**A composed agent that ends on a terminal verdict now fails the composition instead of being swallowed.** An agent mounted in a `Sequence`, `workflow()`, `Conditional`, `Loop`, `Parallel` or `graph()` never reaches its own run boundary, which is where these records become typed errors: a reliability fail-fast, a policy halt, a denied message (input or output), an answer-validation refusal, an evidence-rails refusal. The composition carried on as if the child had answered. `Sequence.step('a', agent).step('b', next)` ran `next` on an empty input and returned its answer. A refusing answer validator's `'final'` was taken for the answer, and an evidence-rails refusal handed the refused answer on. `workflow()` and `graph()` passed the failed agent's whole state to the next step, and `Parallel` counted the branch as a success. Now the agent names its verdict from the state its chart ended with (one translation, shared with its own boundary). `Sequence`, `workflow()`, `Conditional` and `Loop` raise the SAME error the agent raises on its own (class, message, payload) before anything after it runs. `Parallel` and `graph()` report the branch or node as failed through their merge or level join, so a tolerant merge sees `{ ok: false }` for it. This holds in every `reactMode`. Behaviour change: these compositions now reject where they used to resolve. An answer-validation refusal now ends through the final branch's guard rather than a break in the decider, so the trace shows the final branch entered and withheld. Known gaps: the composed error carries no `snapshot`. A `'tell-model'` credential-consent record travels off tracked state, so a composition does not see it.
