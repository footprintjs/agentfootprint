**An abort mid-call is no longer filed as a reliability fail-fast, alone or inside a composition.** With `.reliability(...)` configured, a run cancelled during a model call had its abort routed like a provider failure. It emitted a stray `reliability.fail_fast` event, and in `'classic'` and `'dynamic'` it also wrote the fail-fast record. A rule that retries any error re-asked the cancelled run up to the loop's cap of 50. Inside a `Sequence`, `Parallel` or `Loop` the agent could not see the run's signal at all and retried 7 to 12 times. Now once the run's signal has fired the loop leaves at its next step and rethrows the abort as it came: no rule, no retry, no circuit-breaker count, no `reliability.*` event and no record, in all three `reactMode`s. Behaviour change: every runner (`Agent`, `LLMCall`, every composition) now also hands a signal passed as `run(input, { signal })` or to `resume` to its stages as `env.signal`, as `{ env: { signal } }` already did. Tools therefore see it as `ctx.signal`, and on such a run a stage that calls `$getEnv()` is recorded with `untrackedSources: ['env']`.
