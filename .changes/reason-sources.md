**A doubt names where it came from — and a call is named only in the app's words.** Every reason in `AnswerAssessment.reasons[]` (`agent.assessment()`, `assessAnswer(recording)`) now carries `source`: `{ kind: 'calls', calls: [{ toolCallId, toolName }], unnamed? }` — the calls the reason's own rows name — or `{ kind: 'answer' }` or `{ kind: 'run' }`. The kind is declared once per reason in the reason table, never decided per run; a source holds names and ids only, never an argument, a result or a value; a call the record does not name in full is counted in `unnamed`, never dropped. A tool may declare `defineTool({ displayName: 'loading the attached data' })` — the app's own words, one plain line of at most 60 characters, refused at `defineTool` and at registration when it holds a control, separator or bidi character. The standing line (`.answerLayer({ standingLine: true })`) then names a reason's calls ONLY by it — "Not sure — loading the attached data found nothing." — the declared names named and the rest counted ("… and 1 other call …"); the limits block (`.limitsTravelWithTheAnswer()`) marks each item's declaring calls the same way. Without a `displayName` every line and block is byte-identical; the registered tool name is never the fallback. Naming never changes the standing. The words the line used ride `turn_end.standingLineNames`, so the answer account finds the line again, and its "How sure" counts each reason's calls off the same `source`.
