**How far does this answer stand? `assessAnswer()` and `agent.assessment()` fold it from the run's record — known, consistent with the record, not sure (with the reasons), ask, or not assessed.** The standing is read from what the run COMMITTED, never from how sure the model sounded and never from events, so the running agent and anyone reading the saved recording later get the same answer: `await agent.assessment()` after a run (it loads the fold through `import()` on first use, so an agent that never asks does not carry it), or `assessAnswer(recording)` from `agentfootprint/observe`. A run that paused reads `ask` — every kind of pause (a typed `requestInput`, an `askHuman` question, a tool's `checkIn`, a middleware `ask`), read from the committed state the pause leaves, so the saved recording alone says it and no checkpoint is needed. A run with no answer has no standing: after a run that threw, or whose answer a rule refused, `agent.assessment()` resolves to `undefined` (the typed error carries that verdict). It never says "known" from silence: only a tie to a settled fact supports "known" — today a passed enforce `.answerValidation()` report for these exact bytes — and checks that ran and found nothing read "consistent with the record", never "verified". Each reason names the committed row it rests on: a tool declared ground it did not check (`coverage-gap`), declared that nothing matched (`declared-absent`, including an empty rowset inside a `coverage()` boundary), returned an empty rowset and said nothing about what it searched (`empty-undeclared`), two results the model stood on disagree (`sources-conflict`), names or numbers in the answer appear in no tool result (`value-unsupported` / `value-survived-revision`), a limit cut the turn short (`stopped-early`), or the app's answer checks failed or could not reach a verdict. `checked` lists what actually ran, as counts. It reads this turn only — the results after the last message a person said — so a continued conversation's earlier results are not held against today's answer. A declaration the record lost is still read: when a call has no committed coverage row (a history restored by `resumeOnError` carries the envelope but not the row; a trimmed recording drops it), the envelope in the result is read by the strict recognizer, so an absence and its gap are never read as silence. It is a pure reader: nothing runs inside a run, and every agent's commit log, recording and model requests are the bytes they were.

The `/observe` answer account now renders the same fold in its "How sure" row instead of "The record does not rate how sure this answer is", and `facts.standing` carries the word (`known` · `consistent` · `not-sure` · `ask` · `not-assessed`). Both read results through one emptiness reader, so the account and the standing cannot disagree about what came back: a `coverage()` envelope is read through to its rows (an empty one is a declared absence), a `describedResult()` is counted per kind with the tool's own source and time ("backup_runs returned 2 facts." / "backup_runs says the data came from backup API export, as of 2026-08-19T10:12:00Z."), and a described result that handed back only a question reads `clarify` — a new member of the account's `Emptiness` union, so a reader that switches over it should skip values it does not know. "How sure" says "Ask — …" for a paused run, and "How sure cannot be told: this record does not show the run giving an answer." for a record with no answer and no pause, instead of rating an answer that does not exist; its reason lines count calls, not rows. One reading changes on purpose: an envelope a tool returned as JSON TEXT (an `mcpClient` in text mode), which the run never recognized, is no longer called an absence in "It found" — it is "returned a result", matching "It checked", which never listed it. The standing, which holds no row for that call, still reads the envelope and says "not sure": it may say more than "It found", never less. The account's template set is now version 2.
