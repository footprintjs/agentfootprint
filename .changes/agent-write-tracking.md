type: breaking

**An agent's snapshot keeps a short marker for each write instead of the whole written value, so long runs record a much smaller execution tree.** `writeTracking` joins `readTracking` and `commitValues` on the agent's options and is forwarded to its executor the same way. Its agent default is `'summary'`: each written key in `StageSnapshot.stageWrites` is a `WriteSummaryMarker` (`{ __writeSummary, type, size, preview? }`) rather than the full value. The tree nests one stage inside the next and each pass rewrites growing arrays (`history`, decision lists), so full values grew it with the square of the run length; in one measured 19-call run they were 3.6 of the tree's 3.85 MB. `'full'` keeps today's values, `'off'` records no write view. The commit log, the narrative and every recorder event are unchanged in every mode, and a redaction policy still applies first. `WriteTrackingMode` and `WriteSummaryMarker` are exported beside `ReadTrackingMode`.

Migration: An app that reads written VALUES from `agent.getSnapshot()` or a recording's `executionTree` (`stageWrites[key]`) sets `writeTracking: 'full'` on the agent, or reads the value from the commit log with `commitValueAt`, which every mode keeps. A native capture that the stored-cause tools admit needs `readTracking: 'full'`, `writeTracking: 'full'` and `writeProvenance: 'reads-prefix'` (anything else is `modes-not-supported`), so an agent run meant for those tools sets `writeTracking: 'full'` beside the two it already set.
