**`withRetry` now retries a streaming call that fails before its first chunk.** `stream()` used to be handed straight through, so a streaming run hit by a `429` rate limit or a bare `500` at connect failed outright even under `withRetry` — the only way to survive it was to hand-roll retries inside your own provider. A stream that has produced nothing is exactly as safe to re-open as a `complete()` is to re-send, so `withRetry` now re-opens it under the same policy (`maxAttempts`, `shouldRetry`, backoff, `req.signal`) and reports it the same way: `agentfootprint.error.retried` for each retry and `agentfootprint.error.recovered` once the retried stream's first chunk arrives, before the first `stream.token`. After the first chunk nothing retries — the retry loop only covers opening the stream and returns with that chunk — so a failure mid-stream surfaces exactly as before and no token is ever replayed. A stream that never fails is delivered chunk for chunk as before, and stopping early still closes the inner stream.
