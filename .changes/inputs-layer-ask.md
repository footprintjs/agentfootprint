**The person is asked, once, before anything runs: `askOrAssume`'s `ask` rule (the inputs layer's batch ask).** A tool can now declare that a value the call leaves out is the PERSON's to give — `defineTool({ …, askOrAssume: { window: { ask: 'Which period should the search cover?', choices: ['1h', '24h', '7d'] } } })`. When a batch of calls leaves such values out, the library asks ONCE for everything the batch needs, through the typed ask `requestInput` uses (`isInputPause(outcome)`, `outcome.awaitingInput`, `agent.resume(outcome.checkpoint, { requestId, values })`, rendered and answered by `standingAgent` like any other): a fixed library question, one field per distinct (tool, argument) with the author's question as its description and the author's choices as its enum, positional field ids (`f1`, `f2`, …), and `context.agentfootprint = { ask: 'arguments', fields: [{ id, tool, argument, calls }] }` naming what each field is for. Nothing the model proposed rides the ask. Nothing in the batch runs before the answer — no permission check, no middleware, no dispatch, no assistant turn in history — and the resume adds no model call: the answered values are filled, each call runs on its ordinary path, and its result carries a past-tense note ("window = "24h" … was chosen by the person when asked"). Two period arguments of different tools share one field when their spellings convert (`24h` ↔ `-24h`) and their choices are the same periods. An answer is re-checked against the property's own schema (an integer answered `2.5` does not fit); one that does not fit is asked again with a second fixed question, at most three times, and then the calls that needed it are refused by name. More than 32 fields go in rounds of 32. A partial answer is kept at `Agent.resume`'s door without running anything.

On the record: an `argument` row `asked: 'missing'` for each value asked (filed before the ask, so a snapshot, a checkpoint and a saved recording all carry it), `source: 'answered'` when the answer binds (`free: true` for a free-text field — a name the person typed, never support), `asked: 'invalid-answer'` for an answer that did not fit; one `agentfootprint.findings.argument` event per row. The answer's standing reads `ask` while the question is out — a new reason, `argument-asked`, read from the batch ask's working state (`argumentAsk`) — and the answer account says so ("The run asked the person for values its calls need…"; its template set moves to 4). Beside `.namesAndNumbersFromEvidence()`, the values the person answered are exempt like their own words. `AgentOptions.argumentAskContext` spreads the host's own state into the ask's `context` beside the reserved key (a value that uses the key is refused). A present value on an `ask` argument runs as sent, filed `model` — it is asked about only once the model can declare where a value came from.

One human question per resume: the resume re-runs the batch, so a later call of the SAME batch that needs a person — a check-in, a middleware `ask`, a credential consent, the tool's own `requestInput` — is refused by name in that batch (the law every resume door keeps). The answers such a call carried are KEPT for the rest of the turn and the model is told so ("The person's answer for window was kept for the next purge_logs call that leaves it out, so the call may be proposed again without window."): proposed again with the argument left out, the call runs with the kept answer — filed `answered`, nobody asked again — and pauses for its own step in that batch. A tool with both an `ask` rule and a check-in costs the person two round trips; a kept answer is used once. A credential consent in the batch that asked, under the default `onAuthorizationRequired: 'pause'`, reads the credential's `'tell-model'` sentence; a turn that ends without a later call obtaining the credential raises `CredentialConsentRequiredError` instead of returning the model's answer. The `agentfootprint.pause.resume` event of the library's ask carries the reply's shape with every value `'REDACTED'` — an answer may fill an argument a tool's view hides, and no event carries such a value; every other pause kind's resume event is unchanged. An `ask` rule whose choice the typed ask cannot carry (a blank string, a string over 4096 characters) is refused at definition and dropped at MCP ingest, rather than failing the run at the ask. The ask is raised by the dispatch stage at the very top of the batch, through footprintjs's `interrupt()`, so a resume continues the ReAct loop and works inside a composition (`Sequence`): a pause inside the layer's own subflow would resume into a traversal that cannot reach the loop head on footprintjs 9.26–9.27.

Surfaces that widen, named: `ArgumentFill.source` gains `'answered'`; `ArgumentResolution` gains `ask`; `AssessmentReason` gains `argument-asked` (a reader that switches over every reason must skip one it does not know); `AgentState` gains `argumentAsk` and `argumentAnswersKept`; `PauseResumePayload.resumeInput` reads `'REDACTED'` for each value of a reply to the library's ask. `{ ask: … }` rules, refused at definition since the inputs layer shipped, are now applied — at definition, at dispatch and at MCP ingest. Nothing declared → every run is byte-identical; an agent whose tools declare only `assume` rules is byte-identical to the release before.
