type: breaking
---

Runs now use footprintjs's native lifecycle. Independently mounted components keep separate private state, and cleanup and typed-answer processing remain inside the owning run.

Migration: await each operation before starting another on the same runner. Use separate instances for independent conversations. `RunInFlightError` is the native class: match `ERR_RUN_IN_FLIGHT`; `runnerId` replaces `agentId`, and `activeRunId` can be absent. Its message no longer includes recovery advice. Read run IDs from execution events; `makeRunId` is removed.

Migration: recreate saved pauses with this version. They now retain explicit caller/session origins, finite resource references and the declared tool parties the model saw. Agent resume must keep the paused identity and transport session; its supplied `sessionId` must match. Composition resume does not enforce this Agent-specific transport check. Hosted questions with an unreadable carrier are closed with a notice, so the next message can continue. Missing or inconsistent data refuses before tool effects. Provider IDs are cooperative labels, not authentication. Continue protecting checkpoints at the host boundary.

Migration: retain and answer the returned pause. On a fresh instance, a partial typed answer that has not reached native execution has no local pending-question guard; its checkpoint still holds the question. Hosted agents keep that question in their session store. During a new call's short preparation, snapshot and conversation readers return `undefined`, commit counts are zero and narrative entries are empty. Capture prior records before starting the call. After a leg starts, readers follow it even if it fails; shared-instance readers are not per person, so use one instance per conversation. Known replay and missing-answer refusals occur before origin; without a readable ledger, a spend race or refusal may occur after origin. `followUp` refuses an explicitly conflicting identity.

Migration: custom `RunnerBase` subclasses must supply `initChart`'s execution configuration and initializer, execute through `runExecution().withRun`, use the invocation's view and `execute`, pass that invocation to `detectPause`, and call `noteResumeTakenUp` before resume admission. `lastExecutor` and `openRunRedaction` are gone; use `prepareRunRedaction` and native setup. The corresponding `RunnerInvocation`, `RunnerSelection`, `RunnerMetadata` and `RunnerCoreValues` types are exported. Old subclasses must be rebuilt.

Migration: `session` resource registrations are partitioned by tenant/principal/session and reuse `(tool, scope, key)` within that partition. `shutdown` registrations reuse `(tool, scope, key)` across conversations in the tier. They do not restart an interpreter each turn. `call` and `run` resources use native turn/call ownership, with exclusive borrowing on resume. Pauses retain resources; accepted answers join cleanup. Refused answers restore only a previously held local question; a host store owns transferred questions. A local reference is not a live handle or proof of remote closure. The `agentfootprint.tools.resource_restore` event reports `retained`, `none-known-locally` or `unconfirmed` for local state; remote state stays `unknown`. Use explicit host abandon, close or shutdown controls when discarding a stored question.

Migration: causal memory readers require `schemaVersion: 2` and skip/count older or invalid rows. Evidence covers one component leg, with explicit availability and omissions. Custom evidence callbacks must use their supplied native parent binding, not another run's selected snapshot. Resume creates new observation handles without resetting conversation budgets.

Migration: use `swarm({ agents, router })` instead of separately sequencing `router.route` and `router.step`; the old step chain can pass an empty message. Native event run IDs replace separately minted domain IDs. Log IDs and resume-leg IDs can differ. Records include explicit ownership metadata and may show Messages/System Prompt in a different observed order; preserve recorded order. The fixture manifest pins those named changes and unchanged model-facing content.

Migration: native deadlines can record stage attempts and invoke `onAttempt` for each stage; a non-empty environment can add the native signal to provider requests. Run-scoped `session_closed` can follow `integrity.disposition`. Resume reacquires the current provider catalog once before dispatch, including one additional provider `list` call compared with the old cached path.

Migration: a malformed model batch is refused as a whole only when an actual argument/time ask needs finite checkpoint call IDs. Non-asking batches retain their previous per-call behavior. Saved tool membership discards oldest rows within its finite limits; omitted names are refused on resume until a fresh tool composition supplies the current wire. Empty model text is represented by a library-authored assistant notice before corrective user feedback.
