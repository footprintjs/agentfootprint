**Behavior change: `outputSchema` now defaults to `strategy: 'auto'` instead of `'instruct'`.** A supplied or parser-derived JSON Schema uses native output only when the effective provider positively identifies the model as supported. Anthropic and browser Anthropic use the library's known model table; unknown model names, opaque proxy/deployment aliases, known models without native support, and providers without this declaration keep instruction-based generation with local validation. To retain the previous generation strategy, set `.outputSchema(parser, { strategy: 'instruct' })`. Explicit `strategy: 'native'` keeps its existing forward-compatible policy for unknown model names; no API 400 is automatically retried without the format. The final format guarantee follows the actual request, including reliability fallbacks; it is not a factual accuracy claim. Refusals and truncated native answers still fail; reliability cannot re-ask a native refusal or label a local fallback as native. Object intersections that cannot be safely closed are refused for native output and use the checked path under auto.

Raw JSON and one whole-answer JSON or unlabelled triple-backtick wrapper share the same strict JSON and application-schema validation. Prose around JSON, multiple fences and malformed values still fail, with the original output preserved in errors. Typed runs and claim observations use the same accepted parse.
