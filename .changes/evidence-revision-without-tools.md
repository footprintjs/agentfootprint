**Under an enforcing answer validation, the evidence gate's repair turn calls no tools, so a refund or a send never runs twice before the answer is withheld.** `.namesAndNumbersFromEvidence({ posture: 'guard' })` (or `'rails'`) names an answer's unsupported values back to the model for one more turn, and that turn kept every tool on the wire. Paired with an enforcing `.answerValidation()`, the pairing the docs recommend, a repair could call a tool that writes or sends again, such as a second `issue_refund`, and the answer was then withheld anyway. Now, once the gate asks for its repair under `mode: 'enforce'`, that call and every later call of the run are served no tools. A tool call the model returns anyway is not run: Route ends the turn, and the inputs layer files no argument row for it. The library cannot tell a tool that only reads from one that writes, so none is offered: the model revises from the results it already read, and the repair instruction says so. A run resumed after its repair was asked keeps the tools off. The record says why the list is empty: the call's receipt and the view rebuilt from the commit log carry `tools.withheld: 'evidence-revision'`, and a classifier pick on such a call is not narrowed (`narrowedSkipped: 'evidence-revision'`). Under `mode: 'observe'`, and without an answer validation, the repair turn keeps its tools as before.
