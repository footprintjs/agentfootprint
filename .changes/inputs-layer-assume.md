**A default nobody chose is filled by the library, filed, and admitted: `askOrAssume` (the inputs layer, `assume` only).** A tool can now declare what happens when a call leaves an argument out — `defineTool({ …, askOrAssume: { window: { assume: '2h' } }, period: { argument: 'window', spelling: 'lookback' } })`. The library (never the tool) fills the declared default, files an `argument` row on the findings ledger (`source: 'default'`, stamped with the conversation `turn`), fires `agentfootprint.findings.argument` (names, enums and counts only), and appends a past-tense note to the result the model reads ("the call ran with "2h", the value the tool's rule assumes — recorded as assumed") — one clause per filled value the call really ran with, so a value a before-tool middleware then rewrote is never named. A model that sends the default itself is filed `default` with `proposed`; any other value is filed `model`. The answer's standing (`agent.assessment()`, `assessAnswer`) now reads these rows: `argument-assumed` and `argument-unverified` make it "not sure", with `argument-rules` on `checked`. Under an existing `.limitsTravelWithTheAnswer()`, the answer carries an "Assumed (a tool's rule, not your words)" block. Beside `.namesAndNumbersFromEvidence()`, a declared default is exempt like a value in the system prompt. The library's note is never read as the tool's words: the result message carries a `toolChars` boundary (stripped before every request) that every reader of a result reads through — the evidence gate, the answer's standing, the answer account, and the `unsupported-argument` and `empty-lookup` checks — so the note grounds no value and hides no reading of the result (a filled call's `[]` still reads `empty-undeclared`). The served copy of a ruled schema drops the argument from `required` and says the rule; the registry schema is never edited.

How it arms: a REGISTERED tool that declares `askOrAssume` mounts one small subflow (`sf-inputs`) between the LLM call and Route, run once per batch and only when Route will dispatch it; `AgentBuilder.inputsLayer()` (or `AgentOptions.inputsLayer`) mounts it for ruled tools only a ToolProvider serves. A ruled tool met on an agent WITHOUT the layer is refused rather than run unruled ("…it declares argument rules this agent was not built to apply"), with one warning naming `.inputsLayer()`; this refusal, and the one for rules that cannot be read at dispatch, is decided before any before-tool middleware runs, so no approval is asked for a call that will not run, and a resumed middleware `ask` re-applies both. The rules travel over MCP in `_meta.agentfootprint` (both directions), judged on ingest against the listed tool's own input schema — a rule that fails is warned once and dropped. `{ ask: … }` is judged at definition and refused until the one-ask-per-batch step ships. Nothing declared → every run is byte-identical.

Also: `allow(value, why, { from })` lets a before-tool middleware declare where each rewritten value came from (`'person' | 'app' | 'default'`); under the layer, a rewrite of a ruled argument is filed with `changedKeys` and reads as assumed unless declared the person's or the app's, and the "Assumed" block leaves out a value the rewrite replaced. `LLMMessage.toolChars` is a new framework field (stripped before every request).

Surfaces that widen, named: `FindingsRow` gains the `argument` kind (readers that switch over every kind must skip one they do not know) and every row gains an optional `turn` (stamped while the layer is armed); `agent.findings()` returns rows on an agent without `.findings()` when its tools are ruled, and a continued conversation (`continueFrom`, `resumeOnError`) restores them; an older runtime refuses a checkpoint that carries an `argument` row, and the checkpoint door refuses a row of any kind whose `turn` is not a number. `CheckInRequest.args` is the arguments the call will run with (fills and middleware rewrites applied), not the model's proposal. The answer account's template set moves to 3 (three new lines). Inner dispatch (`ctx.tools.call`) refuses a ruled tool unless every ruled argument is given.
