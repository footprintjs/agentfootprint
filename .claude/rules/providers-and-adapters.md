# Providers, adapters, cache and MCP — seams and blast radius

Loaded only when you work on the paths above — moved verbatim out of the root CLAUDE.md so it costs context only where it applies. **Trust the code** where this disagrees.

## Extension points
- **LLM provider**: `LLMProvider = {name, complete, stream?}` (provider-contract/types.ts:230) passed as `AgentOptions.provider`. `provider.name` keys ONE auto-resolution: Lens labels. The thinking handler is DECLARED (`LLMProvider.thinkingHandler`, read by `thinking/thinkingHandlerFor.ts`; forwarded by every wrapper, `withFallback` only when both sides declare the same handler), and so is the cache strategy: `cache/cacheStrategyFor.ts` · `cacheStrategyFor` reads the provider's DECLARED `promptCaching` (`'breakpoints'` | `'automatic'` | absent → none), and every wrapper must forward that field like `carriesInMessages` (the three resilience decorators do; `withFallback` combines). And so is the thinking SHAPE, per model: `LLMProvider.thinkingMode(model)` → `'budget'` | `'adaptive'` | `'none'`, answered for every Anthropic-body adapter from ONE table (`adapters/llm/anthropicModels.ts` · `ANTHROPIC_THINKING_MODES`; unknown id → `'adaptive'`) through ONE mode function per adapter (`thinkingModeWith` — the adapter's `thinkingMode` option, else the table) that is both declared and handed to `buildMessagesBody` (the one body owner — `anthropic()` builds through it too), so declaration and wire cannot disagree, read by the agent at build (`core/agent/thinkingSupport.ts`: `'none'` → `UnsupportedThinkingError`, `'adaptive'` → dev warning that the budget is not sent). `withFallback` answers the LEAST either side promises. A new Claude model = one table row.
- **MCP retry loop — ONE series per call, two decisions**: `mcp/throttleRetry.ts` · `retryingFetchFor(inner, rules)` runs each call as ONE footprintjs `attempt()` series (used as it ships). Its runner makes an attempt record per try, but they stay inside the module: callers get only `onRetry`, before each wait (kind, attempt, wait, `retryAfterMs`, and the URL's origin + path — `describeUrl` drops userinfo, query and fragment). Saving retry evidence into a run is a later packet. An attempt sends once; a response a rule's `RetryDecision(response, signal)` recognises is THROWN as a `RetryableRefusal` (`code` = its kind, `'throttle' | 'session-busy'`), `retryOn` accepts only those, and a series that ends on one delivers its response (never throws). A response RECEIVED is not an operation that succeeded: a 503 is delivered, never retried. The FIRST rule holds the call's budget (`maxAttempts` → `attempts`, `maxElapsedMs` → `deadline`, plus af's own `maxWaitMs` total, checked in `retryOn`); a JOINED rule's values limit only its own kind. `retryingFetch` = a `throttled` rule (429 only — what `mcpClient` applies to every http/gateway transport); over a fetch registered with `joinableRetry` it JOINS that series instead of wrapping it, which is what keeps the 429 and session-busy retries from multiplying (they used to nest: 3 × 5). The wait is `statedWaitFirst(retryAfter, exponentialBackoff({ …, maxDelayMs }))` (`mcp/backoff.ts`, a stand-in for footprintjs's own helpers): `maxDelayMs` caps the schedule's CEILING before the jittered draw (capped waits keep their jitter) and never a stated `Retry-After`, so the footprintjs policy's `maxBackoffMs` (which would cap every wait) stays UNSET. A stated wait past `maxWaitMs` or the deadline stops the series (the 429 is delivered), never shortened. Under a deadline the attempt's cut stays connected until the answer is CLASSIFIED (the session-busy decision reads a cloned JSON body through `lib/abort.ts` · `bodyChunks`), then lets go — a stalled body is aborted and released, a delivered stream is never touched. The wait itself is footprintjs's timer, not `lib/sleep`.
- **Runtime-hosted MCP (`adapters/mcp/agentcoreRuntime/`)**: an `http` `McpTransport` whose fetch composes session (applied once per request) → retry → auth; session ('per-call', the default, strips both ids and hides the returned `Mcp-Session-Id`; 'reuse' keys each connection by a handle the transport issues, never the server's `Mcp-Session-Id`); auth (SigV4 = `InvokeAgentRuntimeCommand` field mapping in `invoke.ts`; bearer = `createVendingFetch` over HTTPS, because the SDK client's only auth scheme is `aws.auth#sigv4`; machine tokens only); what the MCP client reads of a failure is rewritten from fixed sentences and safe ids on both paths (`safeAnswer.ts`, outside the retry) — never the service's text; a 2xx is read ONCE (`strictJson.ts`), checked and re-serialized — never handed on as raw bytes, ambiguity refused by name.ts`). `mcpClient` must never special-case it.
- **MCP gateway fetch seam (9.32.0)**: `GatewayTransportOptions.fetch?: FetchLike` → `McpGatewayTransport.fetch` → `createVendingFetch(t, t.fetch)` (mcpClient.ts). Composition ORDER is the feature: the credential is vended and applied FIRST, then the consumer's fetch runs — so an mTLS agent / DPoP signer sees the final headers and has the last word while per-request vending survives. Zero vendor code lands here, ever; the secrecy-invariant test extends over the injected fetch. Absent ⇒ `createVendingFetch`'s default global fetch, byte-identical.
- **Ports table** (wired via AgentOptions): PermissionChecker (provider-contract/types.ts:403), PricingTable (:412), CredentialProvider (identity/types.ts:89), CacheStrategy (cache/types.ts · CacheStrategy, chosen by `cacheStrategyFor(provider)` unless `AgentOptions.cacheStrategy` overrides), ThinkingHandler (thinking/types.ts:114 — auto-wire scans HARDCODED SHIPPED_THINKING_HANDLERS, registry.ts:26), ReliabilityConfig (reliability/types.ts:183), OutputSchemaParser (answer-validation/outputSchema.ts · OutputSchemaParser, duck-typed).

## Change-impact map
- **Thinking replay**: actual Anthropic leaf adapters use `anthropicThinkingReplay.ts`; core only carries JSON evidence and records `onReplayPrepared`. Never eagerly prepare an unused fallback. Active known-invalid replay refuses; permitted completed thinking drops emit `agent.thinking_omitted` and retire history. No signature authentication claim, beta auto-enable, or unobserved context removal. SDK/fetch response layout has one owner in `anthropicReplayLayout.ts`.
- **provider-contract/types.ts LLMMessage/LLMRequest** → 62 importers: tool_use round-trip (toolCalls.ts:115-135), wire assembly (callLLM.ts:150-160), providers, cache strategies, security/extractSequence, reliability loop.
- **Cache** → strategy registration is a MODULE SIDE EFFECT (src/index.ts:15-17); an entry point skipping that import silently falls back to NoOp. Resolved once per Agent at construction (Agent.ts:347).
- **Any AWS adapter** (9.4.0) → `test/adapters/aws/awsCommandPin.ts` is THE registry of the SDK command constructors each one dispatches, and its completeness test fails the build for any `src/**` file that LOADS an `@aws-sdk/*` package without a row. Adding/renaming a dispatched command = edit the row. The rule the registry exists to enforce: a bare `@aws-sdk/client-*` **Client is command-based** (`send`/`destroy` only) — per-operation METHOD shortcuts live on the aggregated client (`BedrockAgentCore`), so `client.someOperation(...)` is always wrong here. Three adapters shipped violating this (6.42.0 wrong-service commands, 9.4.0 `EvaluatePolicyCommand` which does not exist, 9.4.0 `agentCoreIdentity`'s method call). Every AWS adapter now has an `_sdk` seam for exactly this test; the AWS SDKs are deliberately NOT devDependencies (six adapters prove their missing-peer-dep refusals by real absence), so the real-module half runs only where they are installed.
