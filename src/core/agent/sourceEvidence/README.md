Walker: actual dispatch capture and bounded find/read flowcharts.
Lens: freshly admitted historical values and fixed unavailable outcomes.

# Native retained-source lifecycle

`capture.ts` is called only by the ordinary native delivery owner and the three
resume owners that actually execute a tool. A human's plain-pause answer is not
a native source execution. Direct tool execution and descriptor callbacks have
no index-write capability. The producer declaration symbol survives transparent
tool copies but is not a tool-schema field.

The invocation-bound publication ledger observes at most 32 native writes and
is sealed immediately at execute return, before asynchronous governance. Only
the final governed, placed, uncapped surface is considered. After-tool denial,
execution failure, pending/invalid status and truncation withdraw capture.
Partial status cannot be promoted by a governed replacement. Coverage and
period come only from the final served wrapper spine; record-only coverage
fields never reappear. Multiple distinct coverage boundaries refuse retention
rather than invent a merge.

A dataset needs both a successful static capture declaration and an exact
returned association. Its key/ref/kind must match; returned fields must be an
exact subset of the declared aliases and paths. A visible ticket alone grants
no field retention. Explicitly selected stored fields are an additional producer
authorization, not a claim that those cells were already on the model wire.
Native publication membership, kind/digest checks and current scoped reads bind
that association to this actual call. Value occurrence does not prove a domain
relationship: the trusted producer owns that mapping.

The small checkpoint index carries references and an omission count only.
Existing host-kept checkpoints are structurally validated, not signed; accepting
an attacker-supplied checkpoint is outside this trust contract. Normal and crash
writers share `sourceEvidenceOf`; `seedIndex.ts` consumes inherited state once.
`checkpointValidation.ts` detaches the already-validated checkpoint carriers
while retaining the original legacy checkpoint object when none are present. An
unmounted Agent refuses an imported carrier. Native pause refuses an absent or
over-cap carrier rather than modifying its engine memento.

Find/read use an actual bounded Footprint flowchart per operation. Query values,
store capabilities, callbacks, payloads and original errors stay in closures;
chart state contains fixed phases and counts only. Errors become a fixed native
break before they can enter stage-failure logging. Cancellation/deadlines end
waiting, detach listeners and prevent later index appends. An already accepted
store write may finish as an ordinary unindexed artifact; no rollback is promised.

Every candidate crosses current producer resolution, native metadata/capability
permission checks and mandatory fresh host admission. Original argument-dependent
execution policy and tool middleware are not replayed from old arguments. The
host admission callback owns current source-scope and privacy authority. Its
projection may only narrow facts/fields and must preserve status, coverage and
period. Receipt integrity/availability is checked again after that callback.

`findingsRecovery.ts` changes only mounted batch-refusal teaching. Admission still
requires unique executed tool-result IDs in the actual accepted request; neither
old IDs nor receipt refs become witnesses. Fixed recovery data permits omitting
unsupported previous entries. It names find/read only when the native current
offer holds both registry readers, with no access/existence claim, subject lookup
or source refresh. Unknown optional operation/scope filters are omitted rather
than guessed. Unmounted refusal bytes and answer/resume terminal decisions
remain unchanged. No domain values or untrusted IDs enter the recovery metadata.

Find cursors contain bounded observation counts/positions, never withheld refs.
New insertions adjust the position without skipping the old page. A byte-filled
page resumes before the first unserved candidate. `find.complete` means the
bounded index scan exhausted with no known index omissions; it says nothing
about failed captures, expired/denied receipts, all historical calls or source
completeness. Array detail pages contain exact permitted values, at most20 rows;
`detail.complete` means the whole retained array fits that response. Source
coverage remains separate. Each page rereads the existing materialized dataset;
there is no payload cache, automatic source query or refresh.
