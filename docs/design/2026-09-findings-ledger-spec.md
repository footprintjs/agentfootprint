# Findings ledger — implementation spec (judged synthesis, 2026-09-16)

Produced by the understand+design workflow (5 seam readers → 3 designs → judge). Fable implements FROM this file; deviations are written back here with the reason.

## Winner: Design 1 — "Ride-along findings" (the `_findings` reserved argument + reserved answer key, zero extra calls). Winner for the cut Fable implements first: every landing line it cites is verified in the 9.100.0 tree (buildToolsSlot :547/:598/:681/:711/:795-796; seed :393; toolCalls :952/:3029/:3052/:3093/:3111/:3150/:3170/:3271/:3424/:3723/:4641/:4830/:4962/:5094; callLLM :361-369/:405-415/:717-724/:786/:875; route :953/:974), its refusals (no synthetic `record_findings` tool, no wrap-up-style answer branch) keep the cut at zero billed calls, and its migration order is shippable. Its two honesty slips (absent standing served as `open`; stratum `asserted` on every assertion; stored `conflicts` groups) are corrected with Design 2's laws; its deferred step 3/4 are taken from Design 3 (wire-only collapse as a bench-gated mode; facts held by the shipped pin grammar, not a new plan shape).

- **Design 1 — Ride-along findings (`_findings`, `findingsLedger: {rows, conflicts}`)** — honesty 4, cost 4, blast 5, measurability 4, total 17: Model's claim recorded under the key it emitted; 'before the call' is a commit-order fact (callLLM :786 commits `llmLatestToolCalls` before Route and dispatch) plus event order (declared → tool_start); history keeps the raw emission, the ledger is a second record; the receipt agrees by construction because the decoration is on the COMMITTED list. Slips: 'absent → served as open' conflates a declared standing with no declaration (must be 'undeclared'); every assertion `stratum: 'asserted'` (an open reading must be `quoted` or it contradicts); `conflicts` groups stored beside rows (values copied twice). Cost: zero extra calls; tokens = one schema property per tool + one instruction piece + the model's `previous[]` echoed in history (shared by all three). Blast radius is the smallest step-2 cut of the three: no integrity read, no checkpoint, no window, no lens, no toolResults change. Measurability: the step-2 'nothing moves' law and new declared/undeclared columns are concrete; step 3's servedAt(k) rewrite is only named.
- **Design 2 — The standing ledger (`findings`, flat append-only rows: basis / standing / conflict)** — honesty 5, cost 4, blast 3, measurability 4, total 16: The best laws of the three and all lifted into the synthesis: absent is undeclared, never 'open' and never a default; the stratum is a DECLARED mapping rule (fact → asserted, open/ruled-out → quoted, noise → none) so only stood-on readings contradict; `epoch` left absent so a fact from iteration 2 can conflict with one from iteration 9; conflict rows carry witness identities, never values, and only for NEW keys; the current conflict set is a fold, so a later ruled-out retires a witness without rewriting a row; model-claimed facts enter integrity labelled `declaredBy: 'model'`. Cost identical to Design 1. Blast radius is the largest: bare `findings` as the reserved name is a plausible author property (a security or audit tool would be refused at build); it refuses provider/MCP-ingested schemas at RUN time; step 2b already touches `unsupportedClaimsOf` + lifecycle registration; `toolResults[].ref` touches five landing sites and the 27 test files that read the entry shape; `outputSchema.ts` gains a peel used by three judge sites; the whole design spans steps 2–5. Measurability equals Design 1's.
- **Design 3 — Standings at every call, pile collapsed on the wire (`$findings`, one row per toolCallId, conflicts derived)** — honesty 4, cost 5, blast 3, measurability 5, total 17: Strongest on served-never-deleted: the ledger piece rides `systemPieces` only, the collapse rewrites CONTENT on the wire and never `scope.history`, the ticket names the toolCallId and ref that redeem the raw bytes, `servedView.viewOf` recomposes both with the same pure functions, 'not yet judged' is served raw and never defaulted to 'open'. Three law breaks: the standing write REPLACES the row (the model changing its mind leaves the key — `claimFacts` says earlier rows are quotable history); 'a disagreeing second carrier is a conflictsOf conflict' is wrong (standings are not assertions; the algebra only sees assertions); `stratum: 'asserted'` on open readings; and `$findings` uses the JSON-Schema keyword sigil (`$ref`/`$schema`) — unverified on Gemini's schema path and OpenAI strict, and `$` is the TypedScope method marker in this codebase. Cost is the best because the collapse offsets the piece on the wire (the baseline pile is 93.5% noise by bytes). Blast radius: collapse changes message hashes between epochs, window strategies measure un-collapsed history, the evidence gate grounds on bytes the model did not see (named, honest direction), the fact HOLD adds a refusal reason and a pins twin, and the integrity join lands in step 2b. Measurability is the best: servedAt(k), noise share of WIRE bytes, the collapse-ticket column, the SHUFFLE run gating the `'ledger-only'` dial.

## Synthesis

ONE design, three sources. The carrier is Design 1's: a reserved optional property `_findings` on every served tool schema (decorated on the COMMITTED list — one site, `buildToolsSlot` after `mergeWire` and before `scope.toolSchemas = merged`, plus the seed fallback — so `servedView` rebuilds it and `receipt.tools.schemaHashes` agree by construction, no new SERVED_GAPS kind), peeled at the dispatch loop head BEFORE `stream.tool_start`, `callArgs`, the permission gate, middleware, `validateToolArgs` (a registry schema with `additionalProperties:false` under 'enforce' would reject it), wants, credentials, execute and every pause carrier; the same peel at the choice seam (`unsupportedArgumentsOf` scans EVERY string leaf of an armed call's args — verified at unsupported-argument/check.ts:220 — so assertion text would file false findings), in `argsForPausedCall`'s history fallback, and on the answer JSON at both judge sites (callLLM `postValidate` runs BEFORE the enforcing decider under reliability). History keeps `toolCalls[].args` VERBATIM (the emission the receipt's message digest hashed; the provider echoes it as tool_use input, so the model re-reads its own standings at no cost). The record is Design 2's: ONE flat append-only `AgentState.findingsLedger?: readonly FindingsRow[]` with three row kinds (basis / standing / conflict), every write a fresh array, last standing row per toolCallId settles and earlier rows are quotable history (the `claimFacts` law), conflict rows written only when the algebra finds a NEW key and carrying witness identities never values, the current conflict set a fold; the stratum is a printed mapping rule (fact → `asserted`, open and ruled-out → `quoted`, noise → no assertions), `epoch` absent, provenance `tool:<toolCallId>` or `artifact:<ref>`; absent is undeclared — never 'open', never a default. The serving is Design 3's, split in two: 3a a request-only system piece composed by a pure `findingsLedgerPiece` from the committed key (the `evidenceRecoveryPiece` twin, in `systemPieces` only — neither exempt from nor evidence for the gate), recomposed byte-equal by `servedView.viewOf`, `ContextSource 'findings'`, the grouped-chart inputMapper line; 3b `collapseJudged` on the WIRE only — noise and ruled-out tool results become an ~80-byte ticket, history untouched, count and toolCallId preserved, `'ledger-only'` (facts collapsed too) a documented dial that stays bench-gated. Eviction is Design 3's bounded HOLD through the SHIPPED pin grammar (`toolResultPinsOf` / `admitPins` / `pinIsBlocking`): 'fact' turns refuse to leave under EVERY strategy up to `keepLedgerFacts` (default 4 when armed) with the two-boundary stand-down; no new strategy file, no non-contiguous plan shape, no meter rebase change — 'noise first' follows because unpinned turns leave oldest-first and 3b has already shrunk them. Decisions taken for the library, with reasons: (1) name `_findings` — letters+underscore is identifier-safe on all seven adapters (each spreads `inputSchema` shallowly: Anthropic `input_schema`, OpenAI `parameters`, Gemini `parametersJsonSchema`, Bedrock `inputSchema.json`), the leading underscore marks framework ownership, bare `findings` collides with plausible author properties, `$` is the JSON-Schema keyword sigil and this codebase's scope-method marker; the name is public and can never change, so the adapter tests land before it does. (2) The vocabulary word is `standing` (fact / open / noise / ruled-out); `disposition` is taken (`integrity/disposition/types.ts:41`). (3) No `toolResults[].ref` field: the placement ticket in `result` is already the one owner of "this result lives at ref" and `isPlacedToolResult` is the library's own predicate over a string the library minted — deriving it at row time is not inference and touches zero of the five result-finalization sites. (4) Basis rows are filed once at the loop head right after the peel (before tool_start and before every pause return, so a paused call's row is on the pre-pause commit); the four resume doors file nothing. (5) A disagreeing second standing is two rows, never a conflict; conflicts are the algebra's output over assertions only. (6) No synthetic `record_findings` tool and no answer-turn branch: an only-synthetic reply becomes 'final' with empty content after `singleProviderCall`'s filter, Anthropic `disable_parallel_tool_use` (AnthropicProvider.ts:351) forbids it beside a real tool, the grouped chart would need a boundary bubble, and a branch costs one billed call per turn replicated across four decider builders; without `.outputSchema()` the last batch is undeclared and served raw. (7) Provider/MCP-ingested schemas that already carry `_findings` are left undecorated (author wins, visible on the committed schema); only REGISTRY schemas are refused at build, and only when `.findings()` is armed. (8) Events carry identities, enums and counts only (the `MiddlewareDecisionPayload` law); values live in the committed key under redaction. (9) The checkpoint carries the ledger value-conditionally (the `folded?` precedent) so a continued conversation never reports its earlier declarations as 'undeclared'. (10) The receipt shape is unchanged through step 4: a dropped turn's standing lives on the committed `WindowRecord`, and the Lens joins an evicted hash to its paired epoch's `ReceiptMessage.key` (= toolCallId) and the ledger fold. (11) The integrity read of ledger assertions (an additive `Assertion[]` witness source labelled the model's claim, advisory-only) and 'ledger-claimed' evidence indexing are NAMED follow-ups, not in steps 2–4: `judgeClaims` runs only on the enforcing decider over a hand-declared `.claims()` contract, and mixing tool truth with model claims without a label is the exact mistake the laws forbid. Everything is gated on the `.findings()` door (`deps.findings` / `hasFindingsLedger`, the `hasEvidenceRecovery` grammar), so an unarmed agent commits the same keys, serves undecorated schemas, mints the same receipt and plans the same window — the 15 byte-identity references never move; each step adds exactly one new reference generated alone. The bench decides at every step: step 2 must not move the six baseline columns; step 3 reads `servedAt(k)` and must move both; step 4 adds the long-run row; the SHUFFLE run on a real model gates any default change. Line numbers above are as of af 9.100.0 (`38cc5b72`); code comments and READMEs cite symbols, not lines.

- Never guess a result's iteration or its tool-calls stage: the standing row carries the DECLARING iteration; the result's own stage is derived from the commit log by toolCallId.
- Never parse a tool result string for a ref except through `isPlacedToolResult` on a string the library itself minted; never add a `ref` field to `toolResults[]` in this program.
- Never file a basis row from a resume door (the pre-pause commit already has it) and never file it after `tool_start` or after a pause `return`.
- Never add a synthetic `record_findings` tool (only-synthetic reply → empty 'final'; `disable_parallel_tool_use`; grouped-chart bubble) and never add a wrap-up-style 'ledger answer' Route branch (one billed call per turn, replicated across four decider builders).
- Never peel the answer key at only one judge site — `callLLM · postValidate` runs BEFORE the enforcing decider and must see the peeled content, or a strict schema loops `outputRetry` on a correct answer; never rewrite `outputAttempts`/the corrective turn's quoted failure to the peeled form (they record the emission).
- Never put assertion values, `settles`, `line` or any model text on the event stream — identities, enums and counts only; values live in the committed key under redaction.
- Never read `findingsLedger` from call-llm or the compact stage without the deps gate (a tracked read of an always-absent key is the phantom-context-source defect).
- Never compose the ledger piece into `systemPromptInjections` (it would exempt every planted value from the evidence gate) — `systemPieces` only, in the fixed order recovery → findings, and never served without `servedView.viewOf` recomposing it with the same function in the same order.
- Never rewrite `scope.history` for serving: the collapse is a wire-only CONTENT rewrite of judged noise/ruled-out tool messages; the window stage stays the only history writer; never drop a message, reorder, or change `toolName`/`toolCallId` on a collapsed entry; never collapse an `open` or undeclared result; never collapse facts by default (`'ledger-only'` is bench-gated).
- Never put the model's words into a library-authored `role: 'user'` line (the drop notice names tools and counts only) and never add a `role: 'user'` construction site without a `LIBRARY_AUTHORED_PREFIXES` entry and a model-facing surface row.
- Never hold a fact turn without a ceiling and a stand-down (the livelock the drop ladder and `pinIsBlocking` exist for); never return a non-contiguous window with the single-seam `rebase` form (the meter silently re-stamps every origin); never change `planRemoval`'s contiguity or the shipped strategies' bytes.
- Never let a lens surface make a claim: LABELS ≤ 7 words, no CLAIM_VERB, data and af library sentences only; omit the band when the key is absent; never hand-author a fixture or a reference.
- Never regenerate the 15 byte-identity references or the 12 lens fixtures wholesale: run the existing ones on the new tree first (they must pass untouched), generate the ONE new scenario alone, diff field by field, and record the delta in the file header.
- Never quote a number before the checked-in bench prints it; never tune the instruction or the piece grammar without a bench run and a new piece hash on the record; never change the `serve` default before the SHUFFLE run on a real model.
- Never thread a `findings` flag into `mcpServe`, `toolDispatch.call` or `withDatasetArtifacts` — those doors carry author args, not the model's, and get no peel and no basis.
- Never widen `Receipt.tools.withheld` for the ledger (a closed literal across receipt, servedView and the lens) — tools stay on the wire; an `open` item may legitimately be fetched.
- Never let the integrity check consume ledger assertions unlabelled or as tool truth — when that packet lands, every such finding says `declaredBy: 'model'` and is advisory when only the model's own earlier claim is contradicted.

### map:call-assembly

Request assembly is one function, callLLM · buildCallLLMStage. It joins committed system pieces (composeRequest · joinSystemPrompt; an optional request-only evidence-recovery piece), strips `injectedBy` from scope.history, takes the tool list from scope.dynamicToolSchemas (EMPTY under scope.wrapUpAsked), and — under 'tool-forced' only — appends deps.schemaTool and sets `toolChoice: {type:'tool', name}` on EVERY call. It mints the receipt (hashes of every system piece, every message incl. tool-call args via messageDigestInput, every tool schema via toolDigestInput, `forced`, `withheld`) into scope.receipt BEFORE the provider is called. After the call, singleProviderCall normalizes a forced answer: readSchemaToolAnswer JSON.stringify's the synthetic tool's args into `content` and filters the call out of toolCalls, so nothing downstream knows the strategy. Then `scope.llmLatestToolCalls = response.toolCalls` and `llmLatestContent` are written and committed in the call-llm bundle; then the choice-seam check (unsupportedArgumentsOf over every string leaf of armed calls' args) runs.

Route · decideBranch picks 'tool-calls' iff toolCalls.length > 0 and neither maxIterations nor a halting cost budget hit; otherwise 'final' (with wrap-up / step-nudge / evidence-recheck / output-retry judged first on the enforcing decider, which also runs the output middleware chain that REWRITES llmLatestContent before judgeAnswer). The Final branch subflow (prepareFinal · captureTurnPayload) copies llmLatestContent → finalContent/newMessages and cannot write back into the run's state.

toolCalls · execute pushes the assistant turn into history with `toolCalls` (args verbatim — Anthropic echoes them as tool_use input on every later call), resets scope.toolResults = [], and per call: `let callArgs = tc.args` → middleware chain → validateToolArgs(callArgs, tool.schema.inputSchema) → check-in → credentials → execute → appends {toolName, result, toolCallId, status} to scope.toolResults and the `role:'tool'` message.

Consequences for the design: (1) BASIS BEFORE THE CALL is already true at zero cost — a reserved field inside the call's args is committed by callLLM (call-llm bundle) before Route runs and before dispatch; (2) the NEXT call's args are the natural carrier for the previous batch's standing, keyed by the tool_result ids the model saw (scope.toolResults[].toolCallId); (3) 'tool-forced' is refused for any agent with tools (AgentBuilder · resolveOutputEnforcement, Refusal 1), so the synthetic tool is only a mechanism precedent — the tool-using agents this design targets run 'instruct' or no schema; (4) the answer turn under 'instruct'+outputSchema has a JSON envelope the decider can peel a reserved key from before judgeAnswer (precedent: the middleware rewrite of llmLatestContent in the same decider); with no outputSchema there is NO structured channel on a no-tool-call reply short of an optional synthetic tool, which conflicts with decideBranch and with Anthropic's disable_parallel_tool_use.

### map:window-eviction

Per iteration (from the second on) the chart loops to `compact`, whose fn is `buildWindowStage`. The stage slices `scope.history`, segments it into Turns (a non-tool message plus its answering tool messages), reads the meter's last usage, `scope.compactions` (prior records), `scope.userMessage` (→ currentRequestIndex), pause state, and builds RemovalGuards with the last-tool-result pin candidates. It calls `strategy.plan(input)` where `input.planRemoval(keepRecent, isExistingSummary?)` is the ONLY way a strategy learns what may leave: it returns one contiguous span [from,to] plus every named refusal, with pins admitted inside it. The strategy returns `{window, rebase, record, evictions, folded?, budgetPressure?, spend?}`; the stage announces `rebase` to the meter (origins = head ++ inserted? ++ tail), writes `scope.history`, files the evicted messages on the iteration-keyed `evictedTurns` handle, stamps `droppedObservations` (tool names whose results left) and pin `observations` onto the record, appends the record to `scope.compactions`, appends `folded` to `scope.foldedSpans` in the same commit, and emits one `context.evicted` per message (hash over the pre-change index). Later in the same iteration `call-llm` reads `evictedTurns.read(iteration)` and mints `Receipt.omittedForAttention = {count, hashes}` where each hash is the turn's own run-salted digest, equal to its `messages.entries[].hash` on the earlier receipt that served it. The Lens (`servedRowAt` → `pairEvictedTurns`) pairs each hash with the latest earlier epoch that served it; `ServedTab · Omissions` prints count + per-hash `epoch N` or Not-on-record; `servedGraphAt` draws withheld edges. Today no eviction carries a reason beyond 'budget' and no receipt row carries a disposition. A strategy today learns NOTHING about standing: its input is the window bytes, counts, and the two bound functions. Dispositions (per the design) would live in a ledger state key written by a findings stage after each tool return, with provenance = the tool result's identity (its `scope.toolResults` entry, which carries `toolCallId`); the join from a Turn to that entry is `turn.messages[i].toolCallId` (the same key `toolNameOfMessage` uses), so the stage — the one place that may read scope — would resolve dispositions per turn and hand them to the strategy pre-bound, like `planRemoval`.

Invariants:

- Tracked state IS the commit log, the snapshot, the narrative and every recording: a key written unconditionally changes every agent's bytes (AgentState doc on wrapUpAsked, toolWantsByName, the repeated-call NOTE) — a new key is written only when the feature is configured and is absent otherwise.
- Committed state is immutable-after-swap: every ledger write is a fresh array (`concat`/spread), never a mutation of the prior value (claimFacts comment).
- Values must survive structuredClone and TypedScope object writes: plain records/arrays only (a Map round-trips to `{}` — toolWantsByName comment); rows carry DETACHED values, never live references into a tool's result.
- Every write must be attributable: contextAt assigns `wroteBy` from the trace row's runtimeStageId; the tool-calls stage is the writer, so the ledger's since-marks land on the existing 'tool-call' milestone stops — no MILESTONES edit needed.
- A finding/disposition/basis is the model's claim recorded as such; a conflict is `conflictsOf`'s output; the library infers none (design law) — the record must carry them as data, never as a lens sentence.
- The lens prints no claim sentences of its own: every ≥2-word literal in walked files must be a LABELS value, a library sentence from 'agentfootprint' (SERVED_GAPS[k].why / UNGAPPED_FIELDS / RECEIPT_BOUNDARY), or the one mandated note; LABELS ≤7 words, no CLAIM_VERB.
- Omit, never deny: an absent key is not rendered as 'none'; a fold that cannot replay reports foldError with no keys.
- ONE cursor: a band reads `cursor.at` / `LensDetailSlotProps.commitIdx`, moves only through `cursor.moveTo`/`onNavigate`, stores no position.
- Fixtures and references are GENERATED from real runs, never hand-authored; the one permitted edit (deleted initialState) is named at its line.
- Grouped chart threading: a key written on the outer scope by tool-calls is recorded with no mapper; reading it inside sf-llm-call requires the outer boundary inputMapper (frozen inside); mutating it inside requires the `next*` alias round trip.
- runtimeStageId is stamped before the stage runs and is the join key between commit log, events and the lens's why band.
